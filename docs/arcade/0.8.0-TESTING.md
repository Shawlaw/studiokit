# Arcade 0.8.0 测试基座：确定性玩法场景与回归

> 状态：**GP003 交付**（分支 `feat/arcade-0.8-gameplay`）。
> 范围：只新增/重构测试工具与本文档，不改游戏文件、不改构建脚本、不进入发布产物。
> 上游依据：[0.8.0-PLAN.md](0.8.0-PLAN.md) 第 3 节；PRD 第 5 节「可测试的游戏性，而不只是 `node --check`」。
>
> 一句话：**`arcade_smoke.mjs` 保证 0.7.0 全链路不回退，`arcade_gameplay_test.mjs` 用固定初始状态 + 稳定场景 ID 断言玩法不变量。**

## 1. 两层测试的职责

| 层 | 文件 | 关注点 | 基线 |
| --- | --- | --- | --- |
| 全链路回归 | `tools/arcade_smoke.mjs` | 门户/中心页、13 款游戏的开始→暂停→存档→续玩、旧档兼容、道具、PWA/断网、320–430px 布局等 85 项 | **85/85**，数量与名称不得因重构减少 |
| 确定性玩法场景 | `tools/arcade_gameplay_test.mjs` | 单个机制的固定状态断言：教学平台可达域、道具状态机、Boss 生成/清关、安全走廊、seed 复现与影冲；GP004/GP005/GP006 起含影冲补充/暂停/旧档恢复、影之试炼 S1–S3、双路线与卷轴复盘 | **11 个场景全部启用**，后续 GP 系列只做加法 |

两层都使用本机 Chrome 的无头模式与零 npm 依赖的 CDP 客户端；任一失败都以非 0 退出码结束。

## 2. 文件布局

| 文件 | 职责 |
| --- | --- |
| `tools/lib/arcade_cdp.mjs` | **通用库**（从 `arcade_smoke.mjs` 抽出）：静态文件服务器（MIME、`/studiokit/` 子路径、403/404、端口可配）、`launchChrome()`、`openPage()`、`CDP` class、`createRecorder()`（`PASS  name` / `FAIL  name — detail` / `x/y … passed`） |

## 3. 运行命令

```powershell
# 语法
node --check tools/lib/arcade_cdp.mjs
node --check tools/arcade_smoke.mjs
node --check tools/arcade_gameplay_test.mjs

# 全链路回归（85 项，约 3–5 分钟）
node tools/arcade_smoke.mjs

# 确定性玩法场景
node tools/arcade_gameplay_test.mjs --list                       # 只列场景，不启动 Chrome
node tools/arcade_gameplay_test.mjs                              # 跑全部场景
node tools/arcade_gameplay_test.mjs --scenario=SC-SL-001         # 只跑一个场景
node tools/arcade_gameplay_test.mjs --scenario=SC-SL-001 --scenario=SC-STAR-001
node tools/arcade_gameplay_test.mjs --scenario=SC-SL-003 --repeat=2   # 同场景连跑 2 遍
node tools/arcade_gameplay_test.mjs --repeat=2                   # 全部场景各跑 2 遍（确定性复跑）
```

输出约定（与 `arcade_smoke.mjs` 相同）：

```text
PASS  SC-SL-003 影跃·种子复现 + 影冲单次动作 — seed=1234, replayEqual=true, platforms=11, …
SKIP  SC-SL-0NN <场景标题> — <pending 原因>（协议示例；当前注册表 11 个场景全部启用，无 pending）
FAIL  SC-… 原因
5/5 scenario runs passed
```

退出码：`0` 全部通过；`1` 有场景失败或运行环境失败；`2` CLI 用法错误（未知参数/未知场景 ID/`--repeat` 非法）。需要本机 Chrome：默认 `C:\Program Files\Google\Chrome\Application\chrome.exe`，可用 `CHROME_PATH` 覆盖。

`pending` 场景：`SCENARIOS` 条目带 `pending: '原因'` 时只打印 `SKIP`，不计入 PASS/FAIL 与退出码（显式 `--scenario` 指定 pending 场景也 SKIP）。钩子交付并实测通过后删除该字段即启用；**不要**用 pending 掩盖失败——启用后的场景必须真实通过。

## 4. 端口、环境变量与并发

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `ARCADE_SMOKE_PORT` | `8765` | `arcade_smoke.mjs` 的静态服务器端口（**默认值保持不变**） |
| `ARCADE_CDP_PORT` | `9333` | `arcade_smoke.mjs` 的 Chrome DevTools 端口（**默认值保持不变**） |
| `ARCADE_GAMEPLAY_PORT` | `8766` | `arcade_gameplay_test.mjs` 的静态服务器端口 |
| `ARCADE_GAMEPLAY_CDP_PORT` | `9334` | `arcade_gameplay_test.mjs` 的 Chrome DevTools 端口 |
| `CHROME_PATH` | 本机 Chrome 默认路径 | 自定义 Chrome 可执行文件 |

- 两个 runner 都只监听 `127.0.0.1`，每次运行创建独立 `mkdtemp` Chrome profile，运行结束清理；因此**可以并发运行**，但必须给每个进程分配不同端口。
- 两个 runner 的默认端口已经错开（8765/9333 vs 8766/9334），默认可以同时跑；若端口被占用，用 env 覆盖：

```powershell
$env:ARCADE_SMOKE_PORT     = '8775'
$env:ARCADE_CDP_PORT       = '9345'
node tools/arcade_smoke.mjs

$env:ARCADE_GAMEPLAY_PORT     = '8776'
$env:ARCADE_GAMEPLAY_CDP_PORT = '9346'
node tools/arcade_gameplay_test.mjs
```

- 排查：`Get-NetTCPConnection -LocalPort 8765`（PowerShell）确认占用者；`Error: listen EADDRINUSE` 表示静态服务器端口冲突，`timeout waiting for http://127.0.0.1:<port>/json/version` 表示 CDP 端口冲突或 Chrome 无法启动。
- `arcade_smoke.mjs` 会在 PWA 断网段主动关闭静态服务器再重启，**不要**在同一端口上并行共用服务器。

## 5. 场景协议

### 5.1 注册表结构

场景是 `tools/arcade_gameplay_test.mjs` 顶部的 `SCENARIOS` 数组元素：

```js
{
  id: 'SC-SL-001',              // 稳定 ID：SC-<GAME>-<NNN>，永不复用、永不重编号
  title: '影跃·前 8 块教学平台不变量',
  game: 'shadow-leap.html',     // apps/arcade/games/ 下的文件名
  pending: '等待钩子上线',       // 可选；有值时只 SKIP，不参与 PASS/FAIL
  async setup(cdp, base) {      // 固定初始状态；base = http://127.0.0.1:<游戏端口>
    // 点击开始 / 切模式 / 设置 seed / forceLand / setLevel ……
  },
  async run(cdp) {
    const info = await cdp.evaluate('window.__arcadeTest.info()');
    assert(条件, '失败原因（会进入 FAIL 行的 detail）');
    return { key: value };      // 证据摘要，格式化进 PASS 行
  },
}
```

约定：

- `id` 稳定是回归可追踪的前提：新增场景用新编号；废弃场景在文档标注 retired，**不要**把编号让给别的机制。
- `title` 用中文短语说明“在断言什么”，会出现在 `PASS/FAIL` 行。
- `pending` 只用于“测试已写好、被依赖的游戏钩子尚未交付”的过渡期：输出 SKIP、不算失败；钩子 stable 后必须删除 pending 并真实跑绿，不允许长期保留。
- `setup(cdp, base)` 只做“进入固定初始状态”的动作；`run(cdp)` 只做观察与状态机操作，失败用 `assert` 抛错。
- 场景内**不写文件、不改持久数据**；需要旧档 fixture 时应通过 `localStorage` / `Arcade.RunSave` 构造（参考 `arcade_smoke.mjs` 旧档兼容段），不要新增 localStorage key。
- 场景只允许使用游戏在 `location.hash === '#test'` 门内暴露的 `window.__arcadeTest` 钩子；**不得**为了测试给正式游玩入口加隐藏作弊路径。

### 5.2 runner 自动提供的固定条件（场景无需重复）

1. 每次运行使用全新的 Chrome profile（`mkdtemp`），进程退出后删除 → 场景之间不会继承浏览器存储。
2. 每个场景开始前：导航到 `/apps/arcade/` 并执行 `localStorage.clear()`。
3. 以 `…/games/<game>?gp003=<id>-<attempt>#test` 强制整页加载（query 防止同 URL 复用，`#test` 打开测试钩子）。
4. 校验运行时与钩子就绪：`window.Arcade`、`window.__arcadeTest`、开始弹层 `[data-overlay]`、`location.hash === '#test'`；任一缺失直接 FAIL。
5. `setup` 与 `run` 前后检查 `cdp.errors`（页面异常 / console.error / Log error）→ 有错误即 FAIL。
6. 每个场景结束截图到 `test-artifacts/gameplay-<id>[-r<attempt>].png`（截图失败不影响判定）。
7. 输出 `PASS/FAIL` 行、最终 `x/y scenario runs passed` 与退出码。

`cdp.waitFor(expression, {timeout})` 用于等待游戏循环把状态推进到目标值（例如 `state === 'playing'`、`featherTimer === 0`、`dashing === false`）；**不要用固定 `sleep` 猜帧**，否则在慢机器上会抖动。

### 5.3 确定性规则

“确定性场景”指：固定初始状态 + 固定断言 + 可复跑。当前分两类：

- **结构不变量**（无 seed 也能稳定）：例如教学平台类型/宽度/间距上限、Boss 生成时 `hp === maxHp`、清关后 `stage + 1`、`stressSpawn(200)` 的安全走廊违规数为 0。断言的是约束，不是随机数值。
- **seed 精确复现**（页面提供 seed 钩子时）：固定 seed 下平台布局、影冲位移等可逐次复现；`--repeat=2` 时证据摘要应完全一致。

写场景时：

- 优先固定 seed（见第 6 节）；没有 seed 钩子的游戏只断言结构不变量。
- 证据摘要只放**稳定值**或布尔值（例如 `corridorPreserved=true`），不要把每帧随机/计时抖动的数值放进证据；断言阈值可以放在 `assert` 里。
- 场景不得依赖真实墙钟（不要断言“运行 30 秒后”）、网络、系统通知、音频播放。
- 必跑：`node tools/arcade_gameplay_test.mjs --scenario=<id> --repeat=2`，再加全量。

## 6. Seed 契约（GP004 起提供）

GP004 已在 `apps/arcade/games/shadow-leap.html` 的 `#test` 门内实现确定性随机（mulberry32），只影响**平台生成**的随机流（`makePlatform` / `platformChance` / `addPlatformAbove` / `reset` 的初始平台），默认仍走 `Math.random`。钩子语义：

| 钩子 | 返回 | 语义 |
| --- | --- | --- |
| `setSeed(seed)` | 归一化后的正整数 seed | 设置随机流；非有限值归一为 `1`，`0` 归一为 `1`；Number/字符串均可 |
| `seed()` | 当前 seed 或 `null` | 未调用过 `setSeed` 时为 `null` |
| `resetWithSeed(seed)` | 平台数量 | `setSeed` + 清局内存档 + 重新生成经典模式平台；**不改变**当前 `state`（ready 仍 ready） |
| `startClassicWithSeed(seed)` | 平台数量 | `setSeed` + 清局内存档 + 重新生成平台 + 进入 `playing`（等价“用种子点开始”） |

使用规则：

1. 场景 `setup` 中用固定常量 seed（例如 `startClassicWithSeed(1234)`），禁止用 `Date.now()` / `Math.random()` 生成 seed。
2. 需要断言“同 seed 复现”时，连续调用 `resetWithSeed(seed)` 两次并比较平台指纹（`x:y:w:kind:range` 拼接），见 `SC-SL-003`。
3. seed 只影响测试生成，不写入正式存档；`resetWithSeed`/`startClassicWithSeed` 会清掉当前局内存档，避免旧局污染。
4. 其余 12 款游戏尚未提供 seed 钩子（GP008+ 按同一契约扩展即可，名字与语义保持一致：`setSeed` / `seed` / `resetWithSeed`；关卡入口用 `startStageWithSeed` 之类的加法钩子）。runner 不强制要求 seed：`SC-SL-001` 做能力检测，有钩子用 seed 固定布局，没有则退回普通开始 + 结构不变量。
5. seed 是**测试生成器**而非玩法随机源；不得让正式游玩入口可被 seed 改变难度或让玩家获得持久收益。

## 7. GP005 / GP006：影之试炼关卡场景

### 7.1 钩子契约（GP005/GP006 已冻结）

场景只允许依赖以下 `#test` 钩子（实现于 `shadow-leap.html` 的 `location.hash === '#test'` 门内；新增/变更先与 shadow-dev 对齐并同步更新本节）：

| 钩子 | 返回 | 语义 |
| --- | --- | --- |
| `stageList()` | `[{ index, id, title, height, start:{x,y}, goal:{x,y,w,h}, platforms, scrolls, routeIds, routes, routeHint }]` | 三关摘要；`platforms` / `scrolls` 是数量，完整平台数组由求解器从源码 `STAGES-JSON` 标记提取 |
| `startTrial(index)` | `boolean` | 清 trialResults/局内存档 + `loadStage(index)` + `state='playing'` + 隐藏弹层；等价「开始试炼」 |
| `loadStage(index)` | `boolean` | 只切关：重建该关世界、重置本关 elapsed/scrolls/dashes/路线进度，不动 trialResults；mode 为 classic 时先置 trial |
| `trialInfo()` | `{ mode, stageIndex, stageId, state, elapsed, player, scrolls, scrollsCollected, scrollsTotal, goal, route, routeLabel, routes, routeInfo, cleared, results }` | 只读快照；classic 下 `mode='classic'`、`stageId=null`；`results[].route` 记录该关路线 |
| `stagePlatforms()` | `[{ x, y, w, kind, range, broken }]` | 当前关平台数组，长度应等于 `stageList()[i].platforms` |
| `forceReachGoal()` | `boolean` | 把玩家放进影门矩形（真实重叠），下一帧判定过关 |
| `forceFall()` | `boolean` | 把玩家移到 `stage.height + 200`，下一帧判定失足 |
| `forceCollectScroll(index)` | `boolean` | 把玩家移到第 index 枚卷轴并由真实重叠收集（`setPosition` 的 y 上限是 740，不能用于卷轴） |
| `trialResults()` | `[{ id, title, time, scrolls, dashes, route }]` | 与 `trialInfo().results` 相同 |
| `routeInfo()` | `{ stageId, route, routeLabel, routeIds, routes, routeHint, exclusiveLanded, sharedLanded, landedRouted }` | GP006 只读路线观察快照 |
| `forceRoute(routeId)` | `boolean` | GP006：立即把本局路线判定记录为该路线，并把玩家摆到该路线一块独占平台上方（不直接清关）；随后 `forceReachGoal()` 的结算文案与 `trialInfo().route` 即为该路线。未知 routeId / 非 trial → false；单路线关传该关唯一 id 返回 true |

状态机与文案契约：

- `state` 在既有 `ready|playing|paused|over` 基础上新增 `'cleared'`（过影门结算）；cleared/over/ready 时 `[data-pause]` disabled。
- 过关结算标题「影门开启」：S1/S2 主按钮「下一关」，S3 后「完成试炼」，btn2「重玩本关」；正文含「用时 / 卷轴 x/y（可选）/ 影冲 n 次 / 路线 <label>」。
- 失足（跌出 `stage.height+60`）标题「失足」，主按钮「从本关起点重试」（**1 次点击**立即重开），btn2「退出试炼」；正文含按关定制的复盘提示与「卷轴是可选的，不影响战力。」
- 路线判定（S2）：落过 fast 独占平台 → `'fast'`；只落 safe 独占 → `'safe'`；两条独占都落 → `'mixed'`；只落共享平台 → `'free'`；开局未落过路线平台 → `null`。路线 label 分别为「稳妥长路」「近路快线」，单路线关为「林间主路」（S1）/「影冲主线 / 侧窗回收回路」（S3）。
- 记录边界：试炼不调用 `Progress.recordPlay`，不写最高分、不写 Playtime 轮次；classic 模式行为与文案保持不变。
- 存档：`runs:v1` 的 `data` 只追加 `mode` / `stageIndex` / `trialElapsed` / `trialScrolls` / `trialResults`（含 `route`）/ `trialDashes` / `trialRoute`（`{exclusive:[],shared:bool}`），旧档缺字段按 classic/未判定恢复；不新增 key、不改 Schema。

### 7.2 注册新关卡场景的步骤

1. **确认钩子**：`node tools/arcade_gameplay_test.mjs --list` 查看场景与状态；在 `shadow-leap.html` 的 `#test` 块确认 7.1 钩子已存在。
2. **追加场景对象**：在 `SCENARIOS` 末尾新增 `SC-SL-00N`（单调编号，不复用），`game: 'shadow-leap.html'`；钩子未 stable 时加 `pending` 字段，stable 后删除。
3. **setup 固定初始状态**：优先用钩子显式进入（`startTrial(index)` / `loadStage(index)`），不要依赖画布坐标点击；用 `cdp.waitFor('__arcadeTest.trialInfo().state === "playing"')` 等待进入关卡。
4. **run 断言**（建议每关 ≥3 条）：
   - 关卡摘要与平台数一致：`stageList()[i].platforms === stagePlatforms().length`，平台字段有限、初始无 broken；
   - 影门/失败路径：`forceReachGoal()` → `state='cleared'` + 弹层标题/主按钮文案；`forceFall()` → `state='over'` + 「失足」+ 1 次点击重试回到 `stageList()[i].start` 附近；
   - 暂停/刷新恢复：暂停后刷新 → 续玩提示 → 点击继续 → `trialInfo().mode==='trial'` 且 `stageIndex/stageId` 一致；
   - 旧档隔离：构造缺少 `mode` 的 classic 存档 → 恢复后 `mode==='classic'`、`stageId===null`；
   - 路线/卷轴（GP006）：用 `forceRoute(routeId)` 固定路线 → `forceReachGoal` → 结算正文含路线 label；`trialInfo().route/routeInfo` 与结算一致；卷轴只写本轮记录、不收集也能通关；
   - 结算/复盘用 DOM 文本断言（`[data-ov-title]` / `[data-ov-text]`），不读 canvas 像素。
5. **必跑验证**：

   ```powershell
   node tools/arcade_gameplay_test.mjs --scenario=SC-SL-007 --repeat=2
   node tools/arcade_gameplay_test.mjs --repeat=2
   ```

   全绿后更新第 8 节清单，并同时跑完整 `node tools/arcade_smoke.mjs`（85 项，经典模式零回归）。

### 7.3 GP006 最终契约（双路线 / 卷轴 / 复盘，已冻结）

## 9. 失败排查

1. 先看 `test-artifacts/gameplay-<id>.png` 与 stdout 的 `FAIL … — 原因`。
2. `#test 钩子缺失`：确认 URL 以 `#test` 结尾、游戏文件仍保留 `location.hash === '#test'` 钩子块；GP004 之后的钩子只允许加法，删除/改名会同时破坏 `arcade_smoke.mjs` 与场景。
3. `页面加载/初始化报错`：`cdp.errors` 已收集页面异常/`console.error`；到浏览器控制台看首个堆栈。
4. 断言数值抖动：大多数是场景在断言随机/计时值；改成结构不变量或使用 seed（第 6 节），等待状态用 `waitFor` 而不是 `sleep`。
5. `EADDRINUSE` / `/json/version` 超时：第 4 节端口覆盖；确认 Chrome 路径。
6. 场景在 `--repeat` 第二遍失败：检查是否残留 localStorage / 未重新导航 / 未清局内存档。
7. 输出 `SKIP` 而不是 `PASS/FAIL`：该场景仍是 `pending`。先确认依赖钩子已交付（`--list` 的 `[PENDING]`），再删除 `pending` 字段实测；**不要把钩子缺失当 PASS**。

本基座只覆盖无头 Chrome（桌面引擎）；**iOS/Android 真机仍为人工验收**，未执行时在任务报告中标注 `UNVERIFIED`。
