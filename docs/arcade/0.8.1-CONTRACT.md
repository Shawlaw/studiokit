## 3. 数据模型：`studiokit:arcade:scores:v1`（Schema v1）

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-11-13T12:00:00.000Z",
  "records": [
    {
      "at": "2026-11-13T12:00:00.000Z",
      "gameId": "block-drop",
      "mode": "classic",
      "score": 1234,
      "lines": 40,
      "level": 5,
      "durationMs": 93000,
      "detail": "40 行 · Lv.5"
    }
  ]
}
```

- 记录按时间**从新到旧**存储（`records[0]` 最新）；上限 `SCORES_LIMIT = 300`，超出丢弃最旧记录。
- `mode` 仅接受 `'classic' | 'zen'`（其他值按 `'classic'` 兜底）。挑战模式不进积分表（挑战有独立的用时/通关记录）。
- `gameId` 必须是 `GAMES` 中的合法 id，否则丢弃。
- `score` 非负有限数（向下取整）；`lines/level/durationMs` 可为 `null` 或非负整数；`detail` 字符串 ≤120 字符。
- 损坏 / Schema 不匹配：**fail closed** 返回空记录，**不删除、不覆盖**原值。
- 旧版本没有该 key：按空记录处理，所有旧数据零迁移。
- `Progress.resetGame(gameId)` 同时清该游戏积分记录；`Progress.resetAll()` 同时清空积分记录。
- 导出/导入：`Progress.exportText()` 增加 `scores` 字段；旧备份没有 `scores` 时**保留当前积分记录**；导入失败回滚包含 `SCORES_KEY`。导入结果增加 `scoreCount` / `scoreSkipped`。

## 4. 引擎 API（`apps/arcade/engine.js`，Owner: engine-scores）

### 4.1 `A.Scores`

```js
const SCORES_KEY = 'studiokit:arcade:scores:v1';
const SCORES_SCHEMA = 1;
const SCORES_LIMIT = 300;

const Scores = {
  SCHEMA_VERSION: 1,
  STORAGE_KEY: SCORES_KEY,
  // 追加一条记录；非法返回 null。成功返回写入的规整记录（含 at）。
  record(entry) -> record | null,
  // 过滤 + 最新优先 + limit；不传 opts 返回全部（最多 300）。
  list(opts) -> record[]        // opts = { gameId?, mode?, limit? }
  // 条数统计：total 为全部，byGame 为 { gameId: count }
  stats() -> { total, byGame },
  // 'zen' -> '禅模式'，'classic' -> '经典'，其他原样字符串
  modeLabel(mode) -> string,
  exportData() -> { schemaVersion, records, updatedAt },
  importData(payload) -> { ok, count, skipped },   // 整体替换；非法 payload ok=false
  resetGame(gameId) -> void,
  resetAll() -> void,
};
```

`window.Arcade.Scores` 必须导出；`list()` 返回副本（浅拷贝数组即可），避免调用方改内部对象。

### 4.2 `A.Progress.recordPlay(gameId, score, meta?)` 扩展（关键集成点）

现有 13 款游戏都调用 `A.Progress.recordPlay(gameId, score)`，这是**统一的积分收集点**：

```js
recordPlay(gameId, score, meta)
// meta = { mode?: 'classic'|'zen', lines?: number, level?: number, durationMs?: number, detail?: string }
```

行为：

1. `plays += 1`、`lastAt` 更新、`lastScore` 更新（原有行为）。
2. **只有 `mode !== 'zen'`（即经典/缺省）才参与 `high` 更新与 `isNewHigh` 判定；禅模式不污染经典最高分**（`lastScore` 仍更新，不影响中心页最高分展示）。
3. 先 `Playtime.recordRound()`（内部计算轮次时长），再把 `{ mode, lines, level, durationMs: meta.durationMs ?? 本轮时长, detail }` 写入 `A.Scores`。
4. 返回值保持 `{ isNewHigh, high, plays }` 形状不变（现有 13 款游戏依赖 `rec.high`）。
5. `Playtime.recordRound(gameId, score, isNewHigh)` 返回 `{ duration }`（毫秒，新增返回字段，调用方只有引擎自己，安全）。
6. `Progress.get()` 返回结构保持 `{high, plays, lastAt, lastScore}` 不变。

## 5. 俄罗斯方块禅模式（`apps/arcade/games/block-drop.html`，Owner: tetris-zen）

### 5.1 模式与入口

- `mode` 取值扩展为 `'classic' | 'challenge' | 'zen'`；旧逻辑默认 classic 不变。
- 开始弹层：主按钮「开始游戏」（经典 40 行）、第二「挑战 6 关」（数据就绪时）、**第三「🧘 禅模式」**（新增 `data-ov-btn3`）。
- 禅模式定义：**无限游玩**（不设 40 行收局，不追加速率关卡上限），速度随消行提升；**用户可随时冻结/恢复提速**。井口堆满仍会结束本局（这是正常收尾，不是失败惩罚），结束/主动结束时把本局积分写入积分记录。

### 5.2 速度模型

- 现有 `gravSec() = max(0.06, 0.8 * 0.85^(level-1))`。
- 禅模式新增 `zenSpeedLevel`：默认 1；未冻结时随 `level` 同步上升（`level = 1 + floor(lines/10)`）；冻结时 `zenSpeedLevel` 不再上升，重力按冻结时的速度保持不变。**恢复提速时立即追平当前 `level`**。
- 非禅模式继续用 `level`，行为零回归。

### 5.3 操作与 UI

- 键盘：`Z` 切换冻结/恢复提速（边沿触发，忽略 repeat；输入框聚焦时不处理）。
- 触屏：画布下方新增 `.zen-bar`（仅禅模式显示），含两个 ≥44px 按钮：「❄ 冻结提速 / ▶ 恢复提速」+「结束本局」。320×568 / 375×667 / 390×844 / 430×932 无横向溢出。
- HUD：禅模式显示 `🧘 禅模式 · 速度 Lv.x`（冻结时带 `· 已冻结`）与行数；DOM 顶栏新增 `data-hud-zen`，禅模式时隐藏「最高」（避免误读为禅模式最高分），保留分数。画布井顶标题在禅模式显示 `ZEN · 速度 Lv.x`。
- 提示文案更新：开始弹层文案说明三种模式；键盘/触屏 hint 补充 `Z 冻结提速`。

### 5.4 结束与积分记录

- 井口堆满：禅模式显示「禅模式结束」结算（分数 / 行数 / 等级 / 用时可选），**不显示“失败”**，可「再来一局」或「回到开始」。
- 结算时调用一次：
  ```js
  A.Progress.recordPlay('block-drop', score, {
    mode: 'zen', lines, level,
    detail: '禅模式 · ' + lines + ' 行 · Lv.' + level,
  })
  ```
  确保 `recordSaved` 只记录一次；禅模式不写经典最高分（引擎契约保证），中心页积分表出现 `禅模式` 行。
- 暂停弹层在禅模式下提供第二按钮「结束本局并记录」（走同一结算路径）；经典/挑战暂停弹层行为不变。
- 关闭/刷新页面：禅模式局内状态进入既有 `runs:v1`（`mode:'zen'` 等字段），刷新后可继续；旧档缺字段按经典恢复不丢局。
