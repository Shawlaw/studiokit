# Arcade 0.8.0《影跃》「影之试炼」S1–S3 手工关卡设计规格

> 版本：竖切片设计稿（对应 Arcade 0.7.0 运行时，不升版本号）。
> 适用范围：`apps/arcade/games/shadow-leap.html` 新增的 `challenge` 模式（GP005 嵌入）。
> 机器可读数据：`docs/arcade/stages-0.8.json`（GP005 原样嵌入 `/* STAGES-JSON-BEGIN */ … /* STAGES-JSON-END */`，标记之间只放纯 JSON 文本）。
> 独立验证工具：`tools/arcade_stage_solver.mjs`（零 npm 依赖，固定步长 1/60 的忠实物理模拟，对每关逐段求解并输出 PASS/FAIL 证据）。
> 本文件只描述 S1–S3；S4–S6 不在本次竖切片内。

## 0. 设计边界（不可破坏的约束）

- **无随机**：所有平台坐标、种类、移动相位都是手写常量；求解器也不使用 `Math.random`（确定性网格搜索，无 seed）。
- **不依赖限量道具**：羽落、月弹不参与任何必经段；求解器完全不建模这两个道具，所有路线仍 PASS，即“无道具可通”。
- **不制造屏外瞬间伤害**：关卡内没有陷阱/伤害体，唯一失败是跌出当前镜头下沿（`player.y > camY + H + 30`；镜头只向上跟随、不回滚）。不存在无预警伤害。
- **起点安全区**：出生点落在起点平台上方；起点平台宽 130–140px，首次着陆 ≤ 0.3s，之后 1–2 秒内没有任何强制操作或危险，给新手观察时间。
- **影门可见**：影门（goal 矩形）位于关卡最顶部、高于全部平台；进入画面后始终在可交互范围内，玩家看到门即知道目标。
- **死亡=跌出当前镜头下沿**：以 `player.y > camY + H + 30` 判定失败（镜头只向上跟随，所以攀得越高、死亡线越靠上，实际比“关卡底部”更严格）；失败后从本关起点复活（不保留跨关进度，进入下一关只由过关驱动）。求解器把死亡线保守地建模为 `y > height`，实际死亡线不晚于该值，因此求解器的可达/回收结论仍然成立。
- **手机操作**：本设计只依赖“左右 + 影冲”三个动作；影冲按钮独立 ≥44×44 CSS px，与左右半屏并发输入由 GP004 输入层保证。
- **暂停/计时**：挑战计时只算有效游玩时间；失焦/锁屏暂停后不推进物理与计时（GP005 接入既有 pause/autosave）。

## 1. 机器可读数据契约（与 `stages-0.8.json` 一致）

坐标：`y` 向下增大；场景宽 420；每关高 1500–2400。平台是**单向平台**，`h` 固定 12（数据中不写 `h`）。

- `start: {x, y}`：**玩家矩形左上角（顶部）坐标**。玩家矩形 26×30（`player.w/h`），所以玩家落点在 `start.y + 30`。所有 `start` 都设计为“底部正好在起点平台顶面上方一点点”，即 `start.y = 起点平台.y - 30`，第一帧即安全落在起点平台并自动起跳。
- `goal: {x, y, w, h}`：影门矩形。玩家矩形与影门矩形相交即过关（上跳穿过或下落穿过都算）。
- `platforms[]`：
  - `normal`：静态单向平台，宽 90–140（S1 推荐 90–130；S2 70–110；S3 主路径 70–130，另有两块回收宽台 R=180、CC=380）。
  - `moving`：`baseX ± range` 正弦横移，`p.phase += speed*dt` 后 `p.x = clamp(baseX + sin(phase)*range, 4, 420 - w - 4)`；`range ≤ 30`，`speed ∈ [0.8, 1.4]`，初相位 `phase = 0`（确定性）。数据里 `x === baseX`。
  - `fragile`：一踩即碎（着陆后 0.22s 移除，期间不再有碰撞）。因为本作“着陆自动起跳”，易碎平台的真实代价是**不能回头二次借力**，逼玩家向前衔接。
- `routes[]`：求解器按段验证的平台索引序列（含起点平台，索引对应 `platforms` 数组）。`requiresDash` 表示“这条路线必须用一次空中影冲才能完成”。S1 有一条 `requiresDash:false` 主线；S2 有两条 `requiresDash:false` 路线；S3 有两条 `requiresDash:true` 路线（影冲主线 + 侧窗回收回路，两者都必经 A→B 的影冲缺口）。
- `scrolls[]`：可选收集，只影响探索记录，不影响战力。`x, y` 是卷轴**中心**；拾取判定用 18×22 的矩形（求解器与实现一致）。
- `targetSeconds`：**首次游玩目标时长**（45–120s，含观察、等待、1–2 次失误重试）。它与“理论最短通关时间”不同：求解器输出的是无失误连续操作的模拟时长（本次数据：S1 10.47s；S2 稳线 11.12s / 快线 7.88s；S3 主线 10.57s / 回收回路 11.68s）；新手首次通常为理论值的 3–5 倍。**本竖切片的验收口径是 `targetSeconds ∈ [45,120]` 且 ≥ 理论最短时间。**
- 判定常量（必须与求解器一致）：`GRAVITY=1500`、`JUMP_V=-640`（落地自动起跳）、`MAX_FALL=900`、`ACC=2400`、`MAX_VX=265`、触墙 `vx *= -0.95`、单向平台着陆容差 0.6px；影冲 `DASH_SPEED=620`、`DASH_TIME=0.13`（1/60 步长下为 8 帧 ≈82.7px）、冲刺期重力 ×0.25、每次着陆补满一次、空中最多一次、落地终止。

## 3. S1「初入影林」

- **ID / 标题**：`S1` / 初入影林（height 1900，18 块平台，1 条路线）
- **学习目标**：左右惯性（加速 2400、最高 265px/s）、落点预判（单向平台只在下落时接住）、宽平台连跳建立节奏。**不教新按键**——本关不需要影冲。
- **必备路线（main，17 块，16 段）**：起点 `S0(140,1680,w130)` 一路到末台 `platforms[17](140,250,w100)`，再上跳穿过影门（goal 186,120,48,64）。
  - 段节奏：竖向间距统一 90px、平台宽 100–130、相邻平台落点区间大多重叠，所以“每一跳都够得着”；真正要学的是**及时把角色挪到下一个落点上方**，而不是极限跳跃。
  - 每段操作：起跳后按“朝下一块平台中心/边缘方向”的方向键 0.2–0.4s，接近落点时松手或反向 0.1s 微调；落到平台会自动再起跳，节奏≈0.68s/段。
  - 容错：平台宽 ≥100 且竖向只差 90（最大上升 136.5），横向误差 ≤60px 都能接住；中途失手通常落回同层或下一层平台而不是直接死亡；掉落可以落到下方已通过平台重新爬升（除起点下方无平台，跌出当前镜头下沿 `camY + H + 30` 才死亡）。
- **可选支路 / 卷轴位置**：`S1-C1` 在 (352, 905)，位于 `platforms[10](40,870,w100)` 右下方约 35px 的空中，玩家从该台起跳后向右下方移动即可撞到（矩形 18×22）。卷轴右侧下方有一块**侧台 SP(290,1000,w100)**（`platforms[8]`）作为回收落点：拿到卷轴后落 SP，再跳回 `platforms[9]/platforms[10]` 继续主线。卷轴**不拿也能通关**，主线路线不依赖它。
- **胜利条件**：玩家矩形与影门 (186,120,48,64) 相交（从末台 platforms[17] 起跳，上升约 66px 即穿过）。
- **失败条件与复活点**：跌出当前镜头下沿（`player.y > camY + H + 30`）即失败，从 S1 起点复活；本关没有其他失败条件。
- **目标时长**：45s（首次；求解器实测无失误连续操作 10.47s）。
- **可练习的技巧**：①“落地瞬间松手/反向”的微调；②连续同向长跳（S1 中段左右横移约 100px）；③不拿卷轴的最短主线。
- **为什么第二次能做得更好**：第二次会知道“不需要满速冲刺”，提前 0.3s 反向或松手就能精准落台；会记住哪些段可以直线通过，哪些段要提前换向。
- **3 条学习证据**：
  1. 首次 30 秒内能完成至少 3 次“有意的横向修正”并落到目标平台（不是靠运气）。
  2. 第二次游玩的重试/失足明显减少（本竖切片不做跨局 `attempts` 统计，以本局结算用时、是否一次通过关键段、以及 Owner 试玩观察记录为准）。
  3. 结算页能显示“本次路线：主线 / 是否收集卷轴”，玩家能说出“卷轴是可选支路”。

## 4. S2「月下断桥」

- **ID / 标题**：`S2` / 月下断桥（height 2150，26 块平台，2 条路线）
- **学习目标**：移动平台**相位**（等它移到自己能落的位置再跳）、易碎平台**快速衔接**（踩到即碎，不能回头二次借力）。
- **公共段落**：起点 `L0(140,2030,w140)` → `L1(70,1935)` → `L2(180,1845)`；顶部公共段 `U0(110,940)` … `FP(150,250)` → 影门 (186,120,48,64)。
- **两条真实不同的路线**（数据里都是 `requiresDash:false`，求解器逐段与整条链路都验证）：

### 4.1 稳妥长路线 `safe`（19 块，18 段）

- 路径：`L0→L1→L2→SA0(40,1755)→SA1移动(30±26,1665)→SA2(100,1575)→SA3移动(40±28,1485)→SA4(130,1395)→SA5(40,1305)→SA6易碎(140,1215)→SA7(50,1125)→SA8(150,1040)→U0→U1(200,830)→U2(100,720)→U3(190,610)→U4(90,500)→U5(170,370)→FP(150,250)→影门`。
- 代价：跳数多（18 段），两段移动平台需要等相位；求解器实测连续通关 11.12s，各段从 972 个起点采样出发的成功率普遍 ≥96%（移动平台段 5832/5832）。好处是平台宽 100–110、落点区间大量重叠、失败后常能落回相邻平台，**风险最低**。
- 每段操作：普通段同上；**移动平台段**先观察平台当前 x，等它移到落点附近（最多等 1–2 次自动起跳）再朝其“预测落点”方向移动；落点区间 = 平台实时 x−24 至 x+w−2。
- 容错：移动平台 ±26/28px 横移，落点区间宽约 118/112px，相位差半周期也仍有可用窗口；易碎 SA6 宽 100，踩碎后立刻起跳去 SA7，不要求回踩。

### 4.2 近路快线 `fast`（16 块，15 段）

- 路径：`L0→L1→L2→SF0易碎(255,1716)→SF1易碎(85,1587)→SF2易碎(255,1458)→SF3易碎(85,1329)→SF4易碎(255,1200)→SF5易碎(85,1071)→U0→顶部公共段→影门`。
- 代价：跳数少 3 段（求解器实测连续通关 7.88s，比稳线快 3.24s / −29%），但 6 块**全部是易碎窄台（w90）**，竖向间距 129px（接近 136.5 的物理极限，留给横向修正的时间仅约 0.53s），而且左右交替 170px：**每一跳都必须提前反向并吃到位移**，错过一次就没有第二次借力，会直接往下掉。这是“更快但更险”的代价。
- 数据上的差异：`safe` 有 2 块 moving + 1 块 fragile + 16 块 normal；`fast` 有 6 块 fragile（全部 90 宽）+ 10 块 normal（3 块起点/分流台 + 7 块顶部合流台），且路线短 3 段。两条路线在 `L2` 分流、在 `U0` 合流，**都真实可通**。容错证据：6 个 129px 易碎段每段从 972 个“平台内落点 × 初速(−220/0/+220)”采样出发有 468 个可过（48%），并非帧级唯一解；整条 `fast` 连续通关 PASS（7.88s）。
- **可选支路 / 卷轴位置**：`S2-C1` 在 (356, 1428)，位于安全路线 `SA4(130,1395)` 右下方约 33px；从 SA4 起跳后向右下方移动可拾取。其下方有侧台 `SP2(300,1520,w100)` 回收：拿到卷轴落 SP2，再跳回 SA4/SA5 继续。卷轴可完全不拿。
- **胜利条件**：任一路线到达末台 FP 后上跳穿过影门。
- **失败条件与复活点**：跌出当前镜头下沿（`player.y > camY + H + 30`）失败，从 S2 起点复活。
- **目标时长**：60s（首次；求解器实测理论最短：safe 11.12s / fast 7.88s）。
- **可练习的技巧**：①读移动平台相位并提前站位；②在 0.5s 窗口内完成“反向加速 + 落到窄台”；③选择“稳”还是“快”。
- **为什么第二次能做得更好**：第一次通常会走稳路并学会等相位；第二次会记住快线的左右交替节奏（左-右-左…），用“提前一拍反向”稳定通过，从而显著缩短用时。
- **3 条学习证据**：
  1. 能说出“移动平台要等它靠近”与“易碎平台不能等”的区别，并在实际操作中体现（移动段有停顿、易碎段无停顿）。
  2. 第二次游玩至少一次主动选择 `fast`（结算记录路线 id），无论成败。
  3. 快线通过次数 ≥1 后，用时比首次稳线下降 ≥20%（本地记录对比）。

## 5. S3「影冲试炼」

- **ID / 标题**：`S3` / 影冲试炼（height 2250，20 块平台，2 条路线：`main` 影冲主线 + `scrollReturn` 侧窗回收回路）
- **学习目标**：单次空中影冲的完整动作“起跳 → 空中按影冲 → 修正落点 → 着陆补满”；理解“影冲主要买的是水平距离，并附带约 60px 的额外上升高度”。
- **影冲主线（main，18 块，17 段，`requiresDash:true`）**：
  - 起步段：`S0(140,2100)` → P1(80,2010) → P2(200,1920) → P3(110,1830) → P4(220,1740) → P5(120,1650) → P6(230,1560) → P7(130,1450) → **回收宽台 R(110,1330,w180)** → 助跑台 **A(296,1200,w100)**。
  - **关键缺口（必须影冲）**：`A → B(6,1070,w104)`。竖直差 130px（<136.5 极限）；水平错位：A 的落点区间约 x∈[272,394]，B 的落点区间约 x∈[−18,108]，**无影冲时最少也要横移 165px**；而 Δy=130 时无影冲的滞空时间上限 0.52s，以 265px/s 极限水平速度最多只能横移 137.8px —— **物理上不可能**。用一次向左空中影冲（8 帧 ×620px/s ≈82.7px 冲刺位移，并把重力降到 25% 换来更长滞空）即可跨过，落在 B 上。求解器连续通关实际计划：`dash(frame=0, dir=-1)`，落点 x≈23。
  - 上段：`B → C1(20,960) → C2(80,850) → C3(10,740) → C4(70,630) → C5(10,520) → Y(140,400) → F(40,310,w120)`。
  - 终点：从 F 上跳穿过**左上角影门** (40,120,48,64)。F 的落点区间覆盖影门左下方，起跳后上升约 96–126px 即穿过。
- **侧窗回收回路（scrollReturn，19 块，18 段，`requiresDash:true`）**：与 main 相同直到 `C5(10,520)`，然后 `C5 → X(280,470,w130) → Y(140,400) → F(40,310,w120)`。这条路线的作用是**验证拿到侧窗卷轴之后的返回路径**：从侧窗掉下来会落到 X，再从 X→Y→F 回到主线去影门。X 不在 main 上（主线是 C5→Y 直达），它只是卷轴回收落点；`C5→X` 是一个偏精确的横向跳（实测 972 个采样起点中 108 个可过，属于可选支路难度），整条 `scrollReturn` 连续通关 PASS（11.68s）。
- **容错（不能必死）**：关键缺口下方有两级回收：
  - 主回收：`R(110,1330,w180)`，覆盖缺口正下方大部分落点；冲短/冲偏会自然落回 R，从 R 再跳 A 重试（R→A 竖直差 120，够得着）。
  - 兜底回收：`CC(20,1490,w380)`，横跨全宽；如果从 A 失败后飘出 R 的范围，会落到 CC，再由 CC → P7(130,1450) → R → A 重试。
  - 求解器实测：关键段 972 次“不冲/冲偏”失败尝试全部落到 R 或 CC（972/972），死亡 0；22356 次“冲晚/冲反”尝试死亡 0。**从 A 到失败落点这一过程不会直接跌出底部死亡。**
- **可选侧窗卷轴（必须影冲）**：`S3-C1` 在 (410, 210)，位于全部平台之上、右上侧窗内。
  - 无影冲时：任何平台都够不到。能进入其接触高度带的只有末台 F(40,310)（竖直差 59–111px，在 136.5px 基础跳跃内）和 Y(140,400)（竖直差 149–190px，基础跳跃根本够不到）；而 F 的水平方向最省也要横移 218px，超过无影冲在该高度的横向可达上限 198.3px。求解器的**全平台无影冲必要上界**扫描没有任何候选，路线平台无影冲搜索也是 0 成功 —— **不用影冲一定够不到**。

## 7. 已知风险与实现注意（交给 GP005）

- `start` 是**玩家顶部左上角**：实现按 `player.x = start.x; player.y = start.y` 放置，落地后立即按既有逻辑自动起跳。不要按中心点解释。
- 影门相交判定用玩家矩形 vs `goal` 矩形（AABB 相交），不是“到达某高度”。到达影门时立即 `finishStage`，不要先播放长动画。
- `moving` 平台必须用 `baseX + sin(phase)*range` 且在更新时 clamp 到 `[4, W-w-4]`；`phase` 初值 0，`phase += speed*dt`。不要用随机相位，否则本关的可达性证明失效。
- `fragile` 平台着陆后 `broken=true`、0.22s 后移除；求解器与实现都必须在“已碎”期间忽略其碰撞。
- 影冲：每次着陆补满 1 次；空中只能触发 1 次；冲刺 0.13s（固定步长下 8 帧）、水平 620px/s、冲刺期重力 ×0.25；冲刺结束把 vx 夹回 ±265；着陆立即终止冲刺并补满。**不要**穿越实心障碍、不要有无敌帧（本关无敌人，但侧窗贴边回弹依赖真实撞墙反弹 0.95）。
- 卷轴拾取矩形 18×22（中心为数据坐标）；收集只写本地探索记录，不改变任何数值。
- 计时只累计 `state === 'playing'` 的有效时间；失焦/暂停不推进物理与计时；重开不读取上一局残留 pointer 状态。
- 相机沿用经典模式逻辑（`camY + H*0.42` 线）；挑战模式的高度直接用世界坐标 `y`，跌出当前镜头下沿（`player.y > camY + H + 30`，镜头只上移）判负；求解器把死亡线保守地建模为 `y > height`。
- 三关的确定性来自数据本身：无 seed 需求（没有随机生成）。若实现侧仍保留经典随机生成，challenge 模式必须完全绕过它。
