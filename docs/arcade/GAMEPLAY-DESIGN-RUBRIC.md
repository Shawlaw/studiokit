# Arcade 游戏性设计量表与单关规格模板（GP002）

> 状态：GP002 交付｜依赖：[0.8.0-FACTS.md](0.8.0-FACTS.md)（GP001 事实冻结）｜适用范围：Arcade 0.8.0 及以后新增机制/关卡的游戏性评审
> 本文件是**验收工具**，不是玩法承诺。它规定“怎样才算有游戏性、需要什么证据、什么情况必须驳回”，供 Agent 自检、独立 Reviewer 复核与 Owner 试玩对照。
> 证据规范：引用仓库文件用相对路径 + 行号/函数名；引用外部设计任务包（PRD/backlog）只用文字章节号，**不写任务包绝对路径**（任务包不入库，见 §8）。

---

## 1. 为什么需要这张量表

0.7.0 已把“可玩性保障”（物理公平、输入、暂停存档、道具、自然终点）做到可用；0.8.0 要补的是**玩法深度**：明确目标、真实选择、可练习技巧、可发现的变化、可理解的反馈、随时可中断。已有回归（`arcade_smoke.mjs` 85 项、`validate_site.py`、13 套 `#test` 钩子，见 [0.8.0-FACTS.md](0.8.0-FACTS.md) §4）只能证明“没坏”，**不能证明“好玩、有选择、值得练”**。因此新增两层工具：

1. **六维量表**：给每款游戏/每个新关卡打 0–4 分，每分必须有证据（§2）。
2. **单关规格模板 + 评审 Gate**：任何新关卡/新机制先写规格、再写代码、最后按 Gate 验收（§3–§5）。

**硬规则**：没有证据的评分按 0 分处理；未实际执行的测试不得写“通过”；无法验证的项必须标 `UNVERIFIED`。

## 2. 六维游戏性量表（0–4 分）

### 2.1 评分卡总览

| 维度 | 一句话定义 | 为什么重要 | 4 分门槛（摘要） |
| --- | --- | --- | --- |
| ① 清晰目标 | 玩家在启动 10 秒内知道“这一局要做什么”，并在 1–5 分钟内有阶段结束或自由收尾 | 没有目标就没有“完成时刻” | 目标一句话可复述；有可见终点/阶段结算；首次 30 秒无需帮助即可开始 |
| ② 选择权 | 至少两个合理选择，风险/收益/时间/资源有可辨认差异 | 没有选择就没有玩家判断 | 存在两条都可行且代价不同的路线/打法；选择结果可复盘 |
| ③ 技巧表达 | 有“初学者能过、熟练者表现更好”的可描述技巧 | 没有技巧就没有重复游玩的理由 | 技巧可命名、可练习、有量化改善证据（同一场景两次结果差） |
| ④ 探索与变化 | 新场景/规律/路线可被发现，且不依赖不可读的随机伤害 | 没有变化就只是同一条流水线 | 有 1 个非必需可发现内容 + 1 个规律/路线变化；不使用无预告随机致命事件 |
| ⑤ 公平与反馈 | 失误原因可归因、危险有预警与反应窗口、挑战可达可解 | 不公平会摧毁信任 | 失败弹层说明原因；危险前有 ≥0.5s 可读预警；可达性有确定性证据 |
| ⑥ 打断友好 | 失焦/锁屏/切应用/刷新能安全暂停并续玩，不损失分数、时限或次数 | 轻量短局的前提 | 3 秒内可暂停；30 秒内回到状态；暂停/中断不扣任何资源 |

### 2.2 每维 0–4 分锚点与必附证据

评分使用整数 0–4。**每个非 0 分都必须填写“证据字段”**；4 分在此之上还要求“可复现 + 可交叉验证”。

#### ① 清晰目标（Clarity）

| 分 | 锚点 |
| --- | --- |
| 0 | 没有目标文案，或目标与结算不一致；玩家不知道如何开始/结束 |
| 1 | 有标题/启动弹层，但目标含糊（如只有“得分更高”），无阶段结束 |
| 2 | 有一句话目标与分数结算；1–5 分钟能进入一次结算 |
| 3 | 目标一句话可见（启动 10 秒内），有明确的胜利/收尾条件与游戏内进度提示 |
| 4 | 3 分 + 玩家在首次 30 秒无需外部帮助即可说出“这一关要做什么”，且 1–5 分钟内必有一次阶段反馈（中段提示/进度条/出口可见） |

**必附证据**：
- `源码位置`：目标文案/终点判定所在文件与函数（如 `finishStage()`、`goal` 判定行）；
- `试玩步骤`：从打开页面到看到目标的 10 秒内操作序列（≤8 步）；
- `场景/seed`：确定性场景 ID 或 seed（用于复现同一目标状态）；
- `证据`：截图/日志路径（截图须含目标文案与 HUD）；
- `评审人/日期`（Agent 自检也要写）。

#### ② 选择权（Choice）

| 分 | 锚点 |
| --- | --- |
| 0 | 唯一正解或纯运气；玩家没有可辨认的选择 |
| 1 | 有操作差异，但收益/风险几乎等价（如左右横移位置随便） |
| 2 | 至少两个选择有可见差异（如快路线 vs 稳路线），但其中一个明显更优 |
| 3 | 存在两个都可行、代价不同（时间/风险/资源/路线）的选择，玩家能说明取舍 |
| 4 | 3 分 + 选择与后续局势联动（前 10 秒的选择改变中段/结算），且两种选择都有成功证据 |

**必附证据**：
- `源码位置`：两条路线的数据/判定（平台布局、分支条件、风险判定函数）；
- `试玩步骤`：分别走两条路线的操作步骤；
- `场景/seed`：两条路线各自的确定性场景 ID（同一 seed 下可复现）；
- `证据`：两次不同路线完成/失败的日志或截图（含结算差异）；
- `代价说明`：一句话写清“选 A 付出什么、得到什么；选 B 相反”。

#### ③ 技巧表达（Skill）

| 分 | 锚点 |
| --- | --- |
| 0 | 结果由随机决定；无技巧描述 |
| 1 | 有操作要求（如“跳准一点”），但无明确练法与改善证据 |
| 2 | 存在可描述动作（如“落地前 0.2s 点影冲”），但未验证熟练后结果更好 |
| 3 | 技巧可命名、可反复练习；同一场景初学/熟练两次结果有差异证据 |
| 4 | 3 分 + 技巧有“越好越明显”的量化指标（完成时间、路线长度、失误次数、资源剩余），并有至少 2 次连续改善记录 |

**必附证据**：
- `源码位置`：技巧对应的判定（冲刺距离/时机窗口/碰撞容差/输入缓冲）；
- `试玩步骤`：慢速示范（第一次）与目标表现（第二次）各一段；
- `场景/seed`：固定场景 ID（同一场景两次对照）；
- `证据`：两次运行的关键数值（时间/失误/分数）与日志；
- `一句话技巧描述`：必须是动作 + 时机 + 结果，如“在最高点前 0.1s 影冲，可跨过 70px 缺口”。

#### ④ 探索与变化（Discovery）

| 分 | 锚点 |
| --- | --- |
| 0 | 每局完全一样且没有新信息；或变化来自不可读随机伤害 |
| 1 | 有视觉变化，但不影响玩法 |
| 2 | 有可选的第二条路线/隐藏区域/规律，但缺少提示或收益 |
| 3 | 有 1 个非必需可发现内容（支路、卷轴、机关、规律），有可读预示，发现后有记录但不提升战力 |
| 4 | 3 分 + 至少 2 种结构不同的变化（如路线变化 + 规律/机制变化），且探索不依赖前置道具、不污染经典记录 |

**必附证据**：
- `源码位置`：隐藏内容/分支的数据与触发条件；
- `试玩步骤`：如何发现（正常玩家可观察到的线索）；
- `场景/seed`：可发现内容的确定性场景 ID；
- `证据`：发现前后截图/日志（如卷轴收集记录）；
- `非必需证明`：默认路线完成记录（不拿探索内容也能通关）。

#### ⑤ 公平与反馈（Fairness & Feedback）

| 分 | 锚点 |
| --- | --- |
| 0 | 必死随机、屏外瞬伤、无预警危险；失败无说明 |
| 1 | 有失败弹层但只有“再来一局”，无原因 |
| 2 | 失败原因可见（坠落/碰撞/时间到），危险可见但预警短 |
| 3 | 失误归因明确 + 危险有可读预警（≥0.5s）+ 失败后可立即重试 |
| 4 | 3 分 + 挑战有确定性可达证据（不使用限量道具也能过）+ 结算给出“下一次练什么”的具体建议 |

**必附证据**：
- `源码位置`：危险生成/预警/判定函数与失败文案；
- `试玩步骤`：故意失败一次 + 正常通过一次；
- `场景/seed`：可达性验证场景 ID（默认路线、无道具）；
- `证据`：失败弹层截图（含原因）+ 可达性测试日志；
- `可达性说明`：不使用限量道具时，默认路线为何可通过（距离/时间/容差）。

#### ⑥ 打断友好（Interruptibility）

| 分 | 锚点 |
| --- | --- |
| 0 | 失焦/切后台仍在推进计时或物理；刷新丢进度 |
| 1 | 有暂停按钮，但自动暂停/恢复不可靠，可能丢状态 |
| 2 | 暂停可用，失焦会暂停，但刷新/页面切换会丢局内进度 |
| 3 | 3 秒内可暂停；失焦/切后台自动暂停；刷新后可恢复局内进度；暂停不计时 |
| 4 | 3 分 + 恢复后 30 秒内可回到原状态且不自动走过反应窗口；中断不扣道具/次数/连击/时限 |

**必附证据**：
- `源码位置`：暂停/自动暂停/存档/恢复函数（如 [engine.js](../../apps/arcade/engine.js) `createLoop` :1300-1376、`bindPause` :1904、`RunSave` :283-358）；
- `试玩步骤`：游玩 → 暂停 → 等待 → 恢复；以及切后台/刷新两条路径；
- `场景/seed`：中断前状态 ID/快照字段清单；
- `证据`：中断前后状态对比日志（分数/计时/次数/位置）；
- `覆盖声明`：真机未测必须写 `UNVERIFIED`，不能只写“结构上支持”。

### 2.4 评分规则（防止“凭感觉给高分”）

1. **证据优先**：某一维缺失任一必附证据时，该维最高只能记 2 分；完全无证据记 0。
2. **4 分需交叉验证**：4 分要求“确定性场景/日志”+“至少一次真人或独立 Reviewer 复核”双证据；Owner 试玩可替代真人复核，但必须记录步骤与观察。
3. **不取平均分**：0.8.0 的立项门槛是**逐维达标**，不是六维平均达标。建议门槛：①③⑤ ≥3 分，② ≥3 分（竖切片关卡至少 S3 需达到），④ ≥2 分（竖切片可先只做 1 条支路），⑥ ≥3 分（0.7.0 基线本就应保持 3 分以上）。
4. **回归不得降分**：新机制不得让某款游戏已有维度的分数下降；若下降，必须在评审中写明原因与豁免理由。
5. **经典模式单独评分**：`classic` 与 `challenge` 分开打分，不能用一个模式的高分掩盖另一个模式的低分（模式定义见 §6.2）。

## 3. 单关规格模板（Stage Spec）

新增关卡**先写规格、再写代码**。规格不完整的关卡不得进入实现；实现后按规格逐项验收。模板字段为强制项（标“可选”的除外）。

```markdown
# 关卡规格：<stageId>

- 所属游戏：<game-id>（文件：apps/arcade/games/<file>.html）
- 模式：challenge
- 版本/作者/日期：<版本> / <Agent> / <YYYY-MM-DD>
- 预计时长：<60–120> 秒（目标区间 45–120 秒；超过 120 秒需说明）
- 学习目标：<一句话：玩家在这一关学到/练习到什么？>
- 前置要求：<需要先掌握的动作/关卡；无则写“无”>
- 关卡数据：<placement 描述或 STAGES 条目摘要；平台/危险/支路/卷轴数量>

## 默认路线（主路径）
- 路线描述：<1–3 步：起手 → 中段 → 收尾>
- 必需动作：<列出技能动作与时机>
- 不使用限量道具是否可达：<是/否 + 依据（距离/时间/容差计算）>
- 胜利条件：<进入影门/到达终点/完成目标，必须有可见判定>
- 预计表现（初学/熟练）：<初学 >X 秒或 >Y 次失误；熟练 <X 秒>

## 风险路线（可选支路）
- 路线描述：<与默认路线不同的代价与收益>
- 风险：<坠落/移动平台/易碎/时间压力，必须有可读预警>
- 收益：<更短时间/探索记录/路线评价，不提升跨局战力>
- 失败后的恢复：<回到哪里重试，代价是什么>

## 失败与复盘
- 失败条件：<掉出屏幕/时间到/次数耗尽等>
- 失败复盘文案（必填，≤2 句）：<例如“你在这块易碎平台停留太久；下一跳提前 0.1s 起跳”>
- 重试方式：<≤2 次点击回到可操作状态；不得强制等待动画>
- 检查点：<关卡入口/房间检查点；不得整关重来除非明确说明>

## 确定性场景与测试
- 场景 ID：<如 SL-S1-default / SL-S2-risk / SL-S3-dash-required>
- seed 或固定布局：<seed 值/固定平台数据；禁止依赖 Math.random 的必过路径>
- 自动化断言：<到终点、不用道具、失败路径、重试后状态、暂停恢复各一条>
- 回归范围：<本关 + 经典无尽 + 旧存档恢复>

## 探索项（可选）
- 探索内容：<卷轴/隐藏区域/机关>
- 发现线索：<视觉预示，不得无提示>
- 是否影响战力：<必须否>
- 记录归属：<挑战记录字段，不进入 classic 最高分>

## 触屏与键盘
- 键盘操作序列：<按键 → 动作>
- 触屏操作序列：<按住/点击区域 → 动作；新增独立按钮 ≥44×44 CSS px>
- 双指并发要求：<是否要求同时按住移动 + 点技能；验收方法>
- 中断检查：<暂停/失焦/刷新后状态保持>
```

### 3.1 字段填写规则

| 字段 | 合格标准 | 不合格示例 |
| --- | --- | --- |
| 学习目标 | 一句话说清“新动作/新判断”，且不是“变快/变小/更多 HP” | “提高难度”“练反应” |
| 默认路线 | 有起手/中段/收尾，能用操作序列描述 | “一直往前跳” |
| 风险路线 | 有明确代价与收益，且两条路都能通关 | “另一条路更近”（无风险/收益说明） |
| 胜利条件 | 有可见判定（出口/终点/目标完成），不是纯分数门槛 | “分数到 1000 自动结算” |
| 失败复盘 | 说明“哪一步错了、下次怎么改”，不是泛泛鼓励 | “再试一次” |
| 可达性说明 | 不依赖限量道具、给距离/时间/容差依据 | “应该能过” |
| 确定性场景 | 有 ID + seed/固定布局 + 可重跑命令 | 只写“手动测试” |
| 触屏+键盘 | 两套操作序列都能完成，独立按钮 ≥44px | 只测键盘或只测触屏 |

## 4. AFK / 无 FOMO 契约（强制）

以下契约对所有新增模式/关卡生效；0.7.0 已具备的能力（见 [0.8.0-FACTS.md](0.8.0-FACTS.md) §2、[engine.js](../../apps/arcade/engine.js)）不得回退。

### 4.1 时间与中断

| 契约 | 要求 | 验收方法 |
| --- | --- | --- |
| **3 秒暂停** | 任意游玩时刻 ≤3 秒内可暂停（顶栏按钮 / `P` / `Esc`）；暂停后不再推进物理、计时、连击、道具时长 | 自动化：暂停后等待 ≥3s，断言状态/计时不变；截图 |
| **30 秒回状态** | 恢复后 ≤30 秒内回到可操作状态；恢复先显示继续提示/安全倒计时，不自动走过玩家反应窗口 | 自动化：暂停 → 等待 → 恢复，记录首次可操作时间；真机复测标 UNVERIFIED 如未做 |
| **1–5 分钟完整体验** | 单次 challenge 关卡目标 45–120 秒；一局 classic 仍保持原有短局节奏；阶段结束有结算 | 关卡规格时长 + 实跑计时日志 |
| 中断不扣资源 | 暂停/失焦/切后台/锁屏不扣道具次数、不扣连击、不推进倒计时 | 对比中断前后快照字段 |
| 只在有效游玩时计时 | 开始/暂停/结算/隐藏/失焦/切后台不计入关卡计时与游玩统计 | 参考 [engine.js](../../apps/arcade/engine.js) `Playtime` :497-546 的 `overlayOpen/visible/focused` 规则 |
| 刷新/重开安全 | 刷新后可恢复局内状态；重开不读取上一局残留的 `pointer.down`/按键状态 | 自动化：加载旧档 → 恢复；断言输入状态复位 |

### 4.2 无 FOMO 硬约束（任一违反即 BLOCKED）

禁止项（新增内容不得引入）：

1. **签到/每日奖励/连续登录天数**；
2. **每日任务/周任务/限时任务/限时回归奖励**；
3. **体力/能量/冷却等待/强制广告/付费抽奖/商店/虚拟货币**；
4. **连续在线奖励、在线时长奖励、跨局战力成长/永久数值升级**；
5. **排行榜/云端竞争/强制登录/成绩上传**；
6. **“错过就没有”的限时内容**；挑战关卡必须随时可重玩；
7. **催促回归机制**（推送、红点、未完成惩罚）。

允许项：本地可选奖章/关卡完成记录/图鉴式探索记录（纯展示，不提升战力、不逼迫回归）；唯一的“提醒”是 0.7.0 已有的**每页面一次、20 分钟有效游玩后的一次性温柔提醒**（不写存储、不强制暂停、不反复催促，[engine.js](../../apps/arcade/engine.js) :505-546、[README.md](../../apps/arcade/README.md) :49）。

### 4.3 记录分离（classic / challenge / assisted）

**事实基线**（决定实现约束）：`progress:v1` 中每款游戏只有 `high/plays/lastAt/lastScore`（[engine.js](../../apps/arcade/engine.js) :851-876）；`runs:v1` 中每款游戏只有**一条**局内快照（:297-306）。因此：

1. **classic 最高分不得被挑战模式写入或覆盖**；挑战完成记录不得改变 classic 的 `high` 语义。
2. **挑战记录独立命名空间**：优先在既有 `runs:v1` 的 `data` 内追加 `mode: 'challenge'`、`stageId`、`seed`、`timer`、`result`、`best: {time, deaths, route}` 等字段（不改 key、不改 Schema）。若要新增独立 key，必须按 [AGENTS.md](../../AGENTS.md) 第 2 节第 3 条（保护用户数据）先给出迁移、回滚与测试方案，并做 ADR；0.8.0 竖切片**不推荐**新增 key。
3. **旧档兼容**：旧 0.7.0 存档缺少 `mode/stageId` 字段时，必须按 **classic** 恢复（不强迫进入挑战、不丢弃旧无尽进度）；恢复函数逐字段 clamp（参考 shadow-leap 道具字段 :403-410 的做法）。
4. **单快照冲突**：若同一游戏已有 classic 未完成局，玩家启动 challenge 时不得静默覆盖。必须二选一：先提示“继续经典 / 放弃并进入挑战”，或把 classic 快照保留到独立字段后再存 challenge；无论哪种，都必须有回归测试证明旧档不丢。
5. **assisted 标记**：使用限量道具/提示的挑战成绩必须单独标记 `assisted: true`，与无辅助成绩分开；不禁止使用，但不得混入同一比较口径。
6. **导出/导入**：挑战记录必须随既有 JSON 备份导出/导入；旧备份缺少挑战字段时仍可导入且不破坏现有数据（参考 [engine.js](../../apps/arcade/engine.js) `Progress.exportText/importText` 与 `RunSave.importMap` :889-950）。
7. **挑战记录只在本机**：不新增上传、排行或跨设备同步；无登录。

## 6. 模式与命名约定

### 6.1 术语

| 术语 | 含义 | 记录归属 |
| --- | --- | --- |
| `classic` | 现有玩法（无尽/原有 6 关/原有 5 关等），默认体验 | `progress:v1` 的 `high/plays`；`runs:v1` 的经典快照 |
| `challenge` | 新增短关/预设局面/模板波次，独立关卡进度与完成记录 | `runs:v1.data` 内挑战字段（推荐）或经 ADR 的独立命名空间 |
| `assisted` | 使用限量道具/提示完成的可比较成绩 | 成绩记录上的独立标记，不混入无辅助口径 |
| `practice` | 可延后；只做关卡重试与提示即可 | 不单独建存储，0.8.0 不强制 |

### 6.2 模式边界

- classic 的难度、结算语义、最高分不得改变；旧档缺少新字段按 classic 处理。
- challenge 必须有独立入口（模式选择/关卡选择），默认不替换 classic；从 classic 进入 challenge 需要明确交互。
- 道具使用状态在可比较成绩中单独标记 `assisted`，不禁止使用。
- 任何模式都不得引入 §4.2 的 FOMO 项。
