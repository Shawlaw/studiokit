# 04｜可解性、工程与真人试玩验收门禁

## Gate 0：静态内容（当前设计包已通过，不代表游戏已实现）

命令 `py -3 scripts/validate_levels.py`，检查全部78关记录、机器校验项目和参考解。若关卡被改动先跑生成脚本，**审查者需看到校验通过的真实终端输出**。

## Gate 1：本地游戏引擎物理与规则（实施者必须新增）

| 游戏 | 不能只靠静态验证的风险 | 需要的运行回放证据 |
|---|---|---|
| 影跃 | 空中惯性/影冲判定、移动桥时机、跳台碰撞 | 每关主路线与可选路线的按帧按键录制，至少初始/边界两种状态 |
| 雪铃 | 弹跳碰撞、错铃顺序、序列可达 | 正确铃链、一次错铃恢复、休止铃、奖励不重复分 |
| 星海突击 | 子弹和玩家速度匹配、弹幕安全区、Boss输出窗口 | 防呆帧录制，标注每次安全通道与Boss伤害窗口 |
| 层塔 | 实际重心偏移、叠塔稳定/倒塔条件 | 每关一组真实释放时间，生成落点与稳定值序列 |
| 俄罗斯方块 | 当前SRS旋转锚点与策划局面解释差异 | 预填残局加载，真实操作可通关，纯经典不变 |
| 极速车道 | 离散安全车道≠换道中间碰撞安全 | 时间展开+真实车宽/速度/换道耗时模拟记录 |
| 黄金矿工 | 摆动到目标角需时间、石头/炸药遮挡、回收时间 | 无道具通关的具体抓取时刻/耗时/结算金额 |
| 砖块计划 | 球的墙角陷阱、门牌碰撞、难击中角 | 可自动模拟多个射球/挡板轨迹，缺少球时重开无死局 |
| 重力翻转 | 从单侧翻到另一侧的时间、尖刺碰撞宽度 | 一组真实翻转事件及无伤路线，最坏帧提前告知距离 |
| 贪吃蛇 | 实现是否正确采纳方向缓存/尾部移动 | 把RLE动作逐逻辑步回放，蛇不会反向或撞尾 |
| 打地鼠 | 时间轴与点击位置、同洞刷新重叠 | 正常点击/错点/多指同秒成功与失败轨迹 |
| 记忆翻牌 | 翻牌期间暂停恢复、限错判定、线索更新 | 配对表回放、失败后立即重试、镜像变换仍成立 |
| 2048 | 按关卡禁随机出块是否影响经典 | 参考滑动回放达到目标、撤销与计步分离 |

没有自动按帧回放能力时，至少提供真实操作录屏+关键状态日志，并标记“尚缺自动可重复证明”；不要用`node --check`作为通关证据。

## Gate 2：移动/暂停

每关 `320×568` 和 `390×844` 模拟预检；每款游戏最少一台真实手机。三种强制场景：

1. 游戏中按住输入并切后台 2 分钟，再回来时所有控制松开、时间不推进。
2. 页面刷新，选择继续，关卡 ID、事件进度、生命、技能、倒计时/棋盘完全一致。
3. 低电量或30fps模式，玩家控制与碰撞不依赖帧率；多指不出现误触、方向粘滞。

## Gate 3：真正的“好玩”

这是 Owner 人工放行，不能由模型自评替代：

- 第二局能否说出“这次我准备练这个动作/路线/解法”？
- 有没有至少两种可辨别的策略选择，其中一种更稳、一种更有风险或效率？
- 玩完一关是否能明确复盘失败原因？没有合理解释的猝死判不通过。
- 练熟后的表现是否真实提升（更快、更准、用更少步、无伤），而非只靠随机刷好局？
- 关卡长度是否符合低时间负担？玩到一半随时离开没有惩罚？

**严格不测/不优化**：每日回访、签到连续天数、社交催促、压迫式通知、戒断焦虑。

## 拒绝条件

任一关未有真实可过路线，不得标DONE；原经典模式异常、存档损坏、触控丢输入、未授权修改生产分支，不得合入；人工试玩体验差可以退回重新策划，但不能“为了按时完成”减少验收。
