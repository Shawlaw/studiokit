## 2. 并行波次

- **Wave 0（串行，约 30–45 分钟）**：T041（Lead，已完成导入/差异/合同）+ T042（平台 Agent）+ T056 骨架上半（测试 Agent 先改造 runner 自动发现）。
- **Wave 1（T042 交付数据/API 后）**：T043–T055 共 13 游戏，按 7 个 Agent 并行：影跃单独；其余 12 款两两分组（见上表负责列）。
- **Wave 2**：T056 下半（测试 Agent 汇总各游戏场景）+ T057（Reviewer 独立复核）。
- **Wave 3**：T058 Lead 集成、文档/队列同步、本地提交。

## 3. 每游戏交付定义（DoD）

1. 6 关从挑战入口可选/可进入；C01 恒开、C0N 需前一关通关；数据严格来自生成文件。
2. 每关有目标提示、可归因失败、2 次点击内重试；挑战记录（完成/最佳/assisted/收集）写入 `challenge:v1`。
3. 暂停/失焦/刷新恢复同一关同一状态；不改写经典最高分/轮次；旧存档安全。
4. `tools/challenge/<gameId>.mjs` 场景：6 关数据与锁定、C01 参考通关（证据等级写明）、失败路径、暂停刷新恢复、经典回归、320/390 无溢出。
5. `docs/arcade/0.9/impl/<gameId>.md` 记录：支持字段、证据等级、设计差异（原值→新值→原因）、未验证项。
6. 全局门禁：`validate_site.py`、`build_site.py`、`node --check`、`arcade_smoke` 85/85、`arcade_gameplay_test --repeat=2` 全绿。

## 4. 不变量与边界

- 经典/无尽模式、0.7.0 道具、自动暂停/局内存档、PWA/离线、13 款原有行为不得回退。
- 不引入框架/构建器/CDN/后端/远程资源；`file://` 仍可直接游玩（challenge 数据用 `<script>` 加载）。
- 不新增其它 localStorage key（仅 `challenge:v1`），不改既有 key/Schema；导出/导入加法兼容。
- `ARCADE_VERSION` 保持 `0.7.0`；发布由 Owner 单独授权（届时再升版本/SW 缓存/注册表/文档）。
- 设计源零修改；数值偏差必须逐条登记。
- 真机 iOS/Android 未测前，所有真机结论一律 UNVERIFIED。

## 5. 已知风险

1. **78 关 × 13 引擎适配是超大工作量**：本波次允许部分游戏以 `NEEDS_REVIEW` 结束；Reviewer 与 Owner 决定是否继续。
2. **物理/弹幕/摆钩/叠塔类关卡**难以完全自动回放，允许 `engine-replay` 证据等级，但必须在 impl 文档中如实标注。
3. **影跃 0.8 旧 S1–S3 存档迁移**是唯一涉及旧挑战局内档的变更，需专门回归。
4. 设计包自检只证明“设计数据存在参考解”，不代表真实引擎可玩；每关仍以引擎证据为准。
