# Arcade 0.8.1 设计：俄罗斯方块禅模式 + 中心页积分记录表

> 版本：Arcade `0.8.1`（2026-11-13）｜Schema：新增 `studiokit:arcade:scores:v1`（v1），既有 5 个 key 与 Schema 不变。
> 需求来源：Owner 当前任务「给俄罗斯方块添加 zen mode 即可以无限游玩 并且支持用户停止速率增加 并且添加游戏积分记录表格收集和展示 你自己推进到发版」。
> 实施契约见 `docs/arcade/0.8.1-CONTRACT.md`（本文件是面向使用者的设计/回滚说明，契约是并行实现的技术基线）。

## 1. 版本命名

本次应用版本取 **0.8.1**，不是 0.9.0。原因：仓库内 `docs/arcade/0.9/` 与「0.9 设计包」已被大量引用为**关卡设计包版本**，而 0.8.0 的应用版本说明中明确写过“目录中的 0.9 不是应用版本”。若本次直接升应用版本到 0.9.0，会在文档、任务队列和后续设计包讨论中持续产生歧义。0.8.1 作为 0.8 系列的功能补充发布，语义上仍是新功能（minor-like），发布证据与回滚方式与 0.8.0 一致。

## 2. 背景与约束

0.8.0 已发布：13 款游戏、78 关挑战模式、`progress/runs/prefs/playtime/challenge` 五个 localStorage key、双端（GitHub Pages + Cloudflare Pages）静态部署。俄罗斯方块当前有经典（新局 40 行收局）与挑战（C01–C06 固定盘面/块序）两种模式，经典最高分写入 `progress:v1`，挑战不进最高分。

本次只加两件事，不重构既有玩法：

1. **俄罗斯方块禅模式**：无限游玩 + 用户可停止速率增加。
2. **积分记录表**：收集并展示每局积分（跨游戏），在中心页以表格呈现。

不引入排行榜/云存档/后端；不新增 CDN、分析或远程资源；不改既有 key 与 Schema；不改变经典/挑战和其他 12 款游戏的行为。

## 3. 功能区一：俄罗斯方块禅模式

### 3.1 入口与模式

- 开始弹层三入口（复用共享 overlay，新增可选第三按钮 `btn3`）：
  - 主按钮「开始游戏」：经典 40 行收局（不变）；
  - 第二「挑战 6 关」：0.9 设计包挑战（不变，数据就绪时显示）；
  - 第三「🧘 禅模式」：本次新增。
- 内部 `mode` 扩展为 `'classic' | 'challenge' | 'zen'`；旧存档缺 `mode` 仍按经典恢复。

### 3.2 “无限游玩”的定义

- 禅模式**不设 40 行收局**，也没有关卡/波次终点；消行只累计分数、行数与等级。
- 井口堆满仍会结束本局（这是正常收尾，不显示“失败”字样），避免出现“永远无法结束”的异常状态；想要继续可立即「再来一局」。
- 不改变 7-bag 随机、踢墙、DAS/ARR、软降/落底、幽灵块、道具等既有规则。

### 3.3 速度与“冻结提速”

- 既有重力：`gravSec = max(0.06, 0.8 × 0.85^(level-1))`，`level = 1 + floor(lines / 10)`。
- 禅模式新增 `zenSpeedLevel`（默认 1）：
  - **未冻结**：随 `level` 同步提升，即正常越来越快；
  - **冻结**：`zenSpeedLevel` 保持不变，重力按冻结时的速度走，等级/行数仍继续累计；
  - **恢复提速**：立即追平当前 `level`（不重置、不缓慢爬升），玩家可自行选择继续挑战更快速度。
- 键盘：`Z` 切换冻结/恢复（边沿触发，按住不重复，输入框聚焦时不响应）。
- 触屏：画布下方 `.zen-bar`（仅禅模式显示）提供 ≥44px 按钮「❄ 冻结提速 / ▶ 恢复提速」与「结束本局」。
- HUD：顶栏 `data-hud-zen` 显示「🧘 禅模式 · 速度 Lv.x」，冻结时追加「· 已冻结」；禅模式隐藏经典「最高」避免误读，分数保留；画布井顶标题显示 `ZEN · 速度 Lv.x`。

### 3.4 结束、结算与积分

- 井口堆满 → 「禅模式结束」结算（分数 / 行数 / 等级 / 用时可选），按钮「再来一局」「回到开始」。
- 暂停弹层在禅模式下提供第二按钮「结束本局并记录」，与井口结束走同一结算路径。
- 结算调用一次 `A.Progress.recordPlay('block-drop', score, { mode:'zen', lines, level, detail })`：
  - 行数计入 `progress:v1.plays/lastAt/lastScore`；
  - **不更新经典最高分**（`high` 仅经典更新）；
  - 写入新积分表（见 §4）。
- `#test` 钩子：`zenInfo/startZen/toggleZenFreeze/zenSetState/zenLineClearScenario/endZen`，供确定性测试复现。

### 3.5 存档兼容

- 禅模式局内状态写入既有 `runs:v1` 的 `data`：`mode:'zen'`、`zenFrozen`、`zenSpeedLevel`（及必要计时字段）。
- 刷新/离开页面后可从「继续上次」恢复，冻结状态与当前速度保留。
- 旧存档没有任何新字段：按经典恢复，不丢局、不强制收局。
- 挑战模式存档字段与恢复路径不变。

## 4. 功能区二：积分记录表（收集 + 展示）

### 4.1 数据模型

新 key `studiokit:arcade:scores:v1`（Schema v1），与既有 key 完全独立：

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-11-13T12:00:00.000Z",
  "records": [
    { "at": "...", "gameId": "block-drop", "mode": "zen",
      "score": 1234, "lines": 40, "level": 5, "durationMs": 93000,
      "detail": "禅模式 · 40 行 · Lv.5" }
  ]
}
```

- 最新在前；上限 300 条（每局一条，超出丢弃最旧，不影响最高分/时长统计）。
- `mode` 仅 `classic | zen`；挑战有独立的用时/通关记录，不进积分表。
- 损坏/Schema 不匹配时 fail closed：读为空表，不删除、不覆盖原值。

### 4.2 收集点

`A.Progress.recordPlay(gameId, score, meta)` 是所有 13 款游戏结算时都会调用的统一入口。引擎在这里：

1. 照旧累计 `plays/lastAt/lastScore`；
2. `mode === 'zen'` 时跳过经典最高分更新；
3. 先计算本轮时长（`Playtime.recordRound` 返回值），再写一条积分记录；
4. 经典模式传入的 `lines/level/detail` 为空时表格显示通用信息，不影响其他 12 款游戏（它们无需改代码）。

因此“收集”是自动的：任何游戏完成一局经典，或俄罗斯方块完成一局禅模式，都会进入积分表；未完成的局（仅自动存档）不进入。

### 4.3 展示

中心页「游玩统计」之后新增「积分记录」区块：

- 表格列：时间 / 游戏 / 模式 / 得分 / 详情；`scope=col`、`caption` 与空状态可读；
- 游戏筛选（全部 + 有记录的游戏）、模式筛选（全部 / 经典 / 禅模式）；
- 默认最新在前，最多展示 50 条，超出提示“仅显示最近 50 条”；
- 空状态说明“任意完成一局后回来查看”；
- 320/375/390/430 布局：表格容器横向滚动，整页不横向溢出。

### 4.4 管理与边界

- 中心页「清除积分记录」只清 `scores:v1`，不动最高分/时长/局内进度/挑战记录。
- 「清除全部记录」与单游戏清除按钮同时清理对应积分（沿用 `Progress.resetAll/resetGame`）。
- 导出备份增加 `scores` 字段；导入旧备份（无 `scores`）时保留当前积分记录；导入失败回滚包含积分 key。
- 与既有 `playtime:v1` 轮次明细的分工：游玩统计关注“时长/轮次”，积分记录关注“分数/模式/详情”，两者可各自清除，互不影响。
- 定位仍是**单机记录**：无排行榜、无跨设备同步、无后端。

## 5. 回滚

- 代码回滚：`git revert` 本次提交并双端重新部署（沿用 RELEASE-RUNBOOK 回滚流程）。
- 数据回滚：`scores:v1` 是纯新增 key，旧版本不读取它；回滚后数据仍留在本机，重新升级即可继续使用。若需要彻底移除，导出备份后清除站点数据即可。
- 不迁移、不删除任何既有 key；`progress/runs/prefs/playtime/challenge` 保持原 Schema。

## 6. 验收（DoD）

- 禅模式：40+ 行后仍处于游玩态（无限）；`Z`/触屏按钮冻结后重力与速度等级不再上升，恢复后追平当前等级；刷新可恢复；结算只记一次。
- 积分：经典一局与禅模式一局各产生一条正确记录；禅模式不改变经典最高分；表格渲染/筛选/清除/导出/导入正确；损坏数据 fail closed。
- 回归：经典 40 行收局、挑战 C01–C06、其余 12 款经典模式零回归；`arcade_smoke.mjs` 85/85；`arcade_gameplay_test.mjs --suite=base --repeat=2` 22/22；新增 `tools/arcade_zen_scores_test.mjs` 全绿。
- 工程：`validate_site.py`/`build_site.py`/全部 `node --check` 通过；320/375/390/430 无溢出；`git diff --check` 干净；双端发布后 `verify_deploy.py` 逐文件一致。

## 7. 已知边界 / UNVERIFIED

- iOS/Android 真机触控（Z 的替代按钮、长按/多指）、低端机帧率仍未做真机验证，保留 UNVERIFIED。
- 积分表只在当前浏览器，本机记录；清除站点数据会丢失（备份可恢复）。
- 禅模式井口堆满即结束，不做“无失败永久清板”设计；若 Owner 需要真正的永不结束体验，可作为后续独立需求评估。
- “冻结提速”不改变软降/落底键对速度的直接控制语义。
