# Arcade 0.9.0 设计：挑战公平性修复 + 三款平和棋牌小游戏

- 版本：Arcade `0.9.0`（`ARCADE_VERSION` / 注册表 / 中心页 / SW `VERSION` 同步）
- 日期：2026-11-20
- 范围：13 款既有游戏的挑战模式公平性与体验修复（不改关卡数据文件）、新增二十一点 / 五子棋 / 纸牌接龙三款单机棋牌、对应测试与版本资产。
- 不变项：`progress:v1` / `runs:v1` / `prefs:v1` / `playtime:v1` / `challenge:v1` / `scores:v1` 的 key 与 Schema 全部不变；挑战关卡数据文件与参考解不变；经典模式最高分语义不变（2048「继续挑战」记录语义修复除外，见 §2.2）。

## 1. 审查方法与证据边界

0.9.0 之前的所有验收都建立在「确定性回放 + 冒烟检查」上：它能证明关卡可解、页面不崩，但不能证明「好玩、公平、有选择」。本版本先做一次逐款只读审查，把问题分成三类：

| 类别 | 判定 | 处置 |
| --- | --- | --- |
| 代码/状态机缺陷 | 能由源码直接证实（道具锁死、续档丢状态、计分算反） | 本版本必须修 |
| 公平性缺陷 | 提示与判定不一致、信息未展示、可刷最佳成绩 | 本版本必须修 |
| 内容密度不足 | 「一关只有一次有效操作」「C04 与 C03 原样重复」等关卡数据问题 | 记录为已知限制，不在本版本重做 78 关（改关卡数据需重跑设计包校验与全部参考解） |

证据等级：本文件的「修复」均有源码位置与自动化断言；**真机手感、真人难度曲线、低端机帧率仍为 UNVERIFIED**，不因自动化通过而宣称已验证好玩。

## 2. 既有 13 款游戏的修复

### 2.1 阻断级（会让玩家卡住或白玩）

| 游戏 | 问题 | 修复 |
| --- | --- | --- |
| 记忆翻牌 | 挑战模式使用「再看一眼」后 `peekTimer` 永不递减，牌面常亮且 `reveal()` 拒绝翻牌，只能退出 | 挑战更新循环按 dt 递减 `peekTimer`/`hintTimer`，到期恢复可翻牌 |
| 记忆翻牌 | 挑战续档不恢复道具次数与计时器，刷新后效果消失、道具补回 | 按经典恢复的字段校验方式恢复 `tools`/`peekTimer`/`hintTimer`/`hintArmed`（clamp） |
| 记忆翻牌 | C05 四象限预览按已过时间切分，最后象限实际 0 秒曝光；C03 末行同样被截断 | 按区域数均分实际 `previewSeconds`，每区至少 0.6 秒，不足则总时长补足 |
| 记忆翻牌 | 暂停文案称「牌面已盖好」，但绘制仍显示未配对牌面 | 暂停/弹层可见时未配对牌面按背面绘制 |
| 2048 | 达成 2048 后「继续挑战」，首次结算已置 `recordSaved`，最终更高分不再写入 | 胜利弹层不写记录；继续后最终结束只记录一次（plays/积分不重复） |
| 砖块计划 | 触屏第一次按住拖动挡板会同时发球 | pointerdown 只记录起点，位移 >8 CSS px 视为拖动；未拖动轻点才发球 |
| 层塔 | 挑战续档强制 `drop=null`、补回箱体与道具：下落中刷新会重开一箱 | 恢复 `drop`/`tools`/`guideArmed` 等字段（clamp），恢复后等待玩家继续 |
| 黄金矿工 | 时间归零时正在回收的钩爪即使已夹中达标也被判失败 | 时间到进入 `resolving`：禁止新放钩，允许当前钩回收入账后再判胜负 |

### 2.2 公平性与可读性

| 游戏 | 问题 | 修复 |
| --- | --- | --- |
| 2048 | 滑动阈值 22 逻辑像素在 320px 屏约 9 CSS px，轻微漂移即触发 | 按 canvas CSS 尺寸换算，阈值取 24–32 CSS px 等效 |
| 俄罗斯方块 | 挑战「换块」不同步固定队列，NEXT 显示与实际出块不一致 | 挑战换块同步 `chQueue`，经典 7-bag 不变 |
| 雪铃 | `drawBell()` 不读 `kind`，休止铃/彩铃/蓝红铃视觉完全相同 | 按 kind 绘制空心、星形、蓝/红等可区分图形 |
| 雪铃 | 挑战中「安可」扣次数且标 assisted，但没有任何效果 | 挑战模式禁用该道具（不消耗），保留经典效果 |
| 砖块计划 | C03/C06「撞未解锁门伤钥匙」只在事后 Toast 说明 | 挑战中常驻锁定门/钥匙图标与提示文案 |
| 层塔 | 挑战绿色对齐提示用经典 85% 重叠，可能指向错误位置 | 挑战按关卡 `targetOffset±tolerance` 判定，显示预计偏差 |
| 层塔 | 结算「倾斜峰值」实际是当前值 | 记录本局真实最大倾斜 |
| 黄金矿工 | 玩家看不到矿物价值/重量，却要做价值-时间决策 | 场上标注价值与重量（轻/中/重） |
| 极速车道 | 近距超车只给 5 分，普通通过给 10 分，奖励方向算反 | 基础 10 分 + 近距奖励 5 分 |
| 极速车道 | C02 首时隙占用出生车道，读目标时可能已失败 | 进入挑战时若出生车道被占用，自动移到该时隙安全车道并提示 |
| 影跃 | 重试保留检查点但清零计时，可故意死亡刷更短最佳成绩 | 最佳成绩用整次挑战累计时间（跨重试累加），存档恢复累计值 |
| 影跃 | 易碎平台看不出何时会碎 | 按 `crackTimer` 绘制裂纹/透明度变化 |
| 星海突击 | 挑战刷新后 Boss `fireTimer` 被重置为 999，拾取游标未保存 | 恢复 Boss 计时与拾取游标（旧档安全默认值） |
| 星海突击 | 挑战顶部 DOM HUD 与画布 HUD 重叠 | 挑战模式隐藏重复 DOM HUD |

### 2.3 已知限制（本版本不修，如实记录）

- 部分关卡内容密度不足：俄罗斯方块 C04 与 C03 目标落点重复、2048 C05 一步可解、影跃 C01–C06 参考通关 1.9–4.5 秒。修这些需要同时改设计源、生成器、夹具与参考解，并重跑设计包 1088 断言；本版本只修「判定/提示/续档/计分」这类不改关卡几何的问题。
- 挑战最佳成绩仍以「用时」为主口径，可能鼓励背固定解法；本版本只保证计时不被重试污染，未改记录 Schema。
- 星海 C03「无碰撞」与判定口径若数据未提供零伤字段，则统一为 HUD 文案与判定一致，不新增隐藏规则。
- 重力翻转设计文档中的「推荐翻转窗口晚半段」风险未在本版本重新校准（该窗口只用于测试回放，未在玩家 UI 展示）。

## 3. 新增三款平和单机棋牌

三款游戏都遵守「快乐不用赶进度」：无倒计时、无下注、无体力、无签到、无每日奖励、无联网与排行榜；每局可随时暂停，离开自动存档。

### 3.1 二十一点 · 静局（`blackjack.html`，难度 1）

- 单副牌，每手重新洗牌；一局固定 6 手；只有「要牌 / 停牌」两种决策，A 自动 11/1 最优。
- 计分：赢 +100、平 +25、普通 21 点 +150、Blackjack +250，庄家 17 点停。
- 可选道具：🂠 换一张（1 次/局）、👁 看底牌（2 次/局）。
- 交互：画布内三枚大按钮 + 键盘 H/S/空格；底部 2 个 44px 道具按钮。

### 3.2 五子棋 · 静局（`gomoku.html`，难度 2）

- 11 路棋盘，玩家执黑先行，对本地启发式 AI（先胜、再堵、后评分；种子可复现）。
- 触屏采用「先点预览、再点确认」，避免格点误触；坐标标签 A–K/1–11。
- 可选道具：↩ 悔棋（3 次/局）、💡 提示（2 次/局）。
- 计分：胜 = max(300, 1000−10×步数)，平 300，负 0。
- **实测点按粒度（如实披露）**：画布逻辑 420×740 经 CSS 等比缩放后，390/430px 视口下格距约 30–34 CSS px、棋盘约 355px；但 **320×568 下画布仅约 168 CSS px，格距约 13.6 CSS px**、375×667 约 18.4 CSS px。因此 320/375 的格点小于 44px 触控目标，只能靠「先预览再确认」降低误触，**真机精度仍未验证（UNVERIFIED）**。

### 3.3 纸牌接龙 · 静局（`solitaire.html`，难度 2）

- 标准 Klondike 抽 1 张，可无限翻回牌库；点选牌 → 点目标完成移动（不依赖拖拽）。
- 失败无惩罚：牌库可反复翻、撤销 10 次、提示 3 次。
- 计分：基座牌×10 + 已翻开列牌×5 − 移动次数（最低 0）。
- **实测点按粒度（如实披露）**：390/430px 视口下牌面约 39×55 CSS px；320×568 下画布约 168 CSS px，牌面约 20×28 CSS px、明牌叠放步进约 8 CSS px、顶栏槽位约 18 CSS px，均低于 44px。交互以「先选牌、再点目标列/基座」替代拖拽；320/375 真机精度仍为 UNVERIFIED。

### 3.4 接入契约（三款一致）

- 共用 `engine.js` 的 `createStage/createInput/createOverlayUi/createRunAutosave/createToolbelt/bindPause/createLoop/Progress/Scores`。
- 开始弹层默认「开始游戏」；结算「再来一局」回到开始弹层重新选模式；暂停弹层支持「继续」与提前结束记录。
- `window.__arcadeTest.selftest()` 覆盖规则确定性断言，`playToEnd()` 走真实结算路径，`regression()`（既有 13 款修复项）供 `arcade_calm_games_test.mjs` 调用。
- 布局：320/375/390/430 无溢出，画布外 2 个 ≥44px 道具按钮，无 console error。

## 4. 兼容性与数据

- 三款新游戏使用既有 `progress:v1`（最高分/局数）与 `runs:v1`（局内快照），**不新增任何 localStorage key**；与既有 13 款一样，结算会经共享运行时写入 `playtime:v1` 与 `scores:v1`（这是既有行为，不是本版本新增 key）。
- 既有 13 款游戏的 key、Schema、挑战数据与参考解不变；修复只改运行时逻辑与展示。
- 2048「继续挑战」的记录语义变化：一次胜利后继续，最终结算才写入一条积分记录（此前会丢失最终分数）；旧记录不受影响。
- 导出/导入格式未新增字段（`challenge` 字段自 0.8.0 起已存在），旧备份仍可导入；新游戏数据同样只走 `progress`/`runs`/`playtime`/`scores`。
- 其它随修复产生、需告知的行为变化：
  - 黄金矿工的「时间到后允许当前钩回收」同时作用于经典与挑战；
  - 俄罗斯方块挑战失败弹层新增一句本关技巧建议；
  - 2048 挑战目标文案在展示层按实际步数上限改写（不改关卡数据）；
  - 雪铃挑战禁用「安可」且不消耗次数；
  - 影跃最佳成绩改为跨重试累计时间，旧档累计值按 0 起算。

## 6. 回滚

- 单款回滚：恢复对应 `games/*.html` 到 0.8.6 版本即可；三款新游戏可先从 `engine.js` 的 `GAMES` 移除并保持文件（中心页与 SW 自动不再引用）。
- 版本回滚需同步 `engine.js`、`sw.js`、注册表、`validate_site.py` 断言与 README/CHANGELOG，避免版本一致性检查失败。
- 不回滚/删除任何 localStorage 数据。
