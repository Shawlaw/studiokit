# 街机厅 0.4.0 设计说明：全屏沉浸 & 黄金矿工道具

状态：已实现，等待 Owner 试玩确认
范围：`apps/arcade/engine.js`、`apps/arcade/arcade.css`、`apps/arcade/games/gold-miner.html`
不改变：局内档 key / Schema、最高分 key、游戏清单结构、离线优先约束

---

## 1. 问题

移动端浏览器里，一局游戏真正能看到的画面只有中间一块：

```
┌──────────────────────────┐
│ StudioKit / 街机厅  (38px) │  ← 站点 shell
│ ‹ 街机厅  ⛏ 黄金矿工  HUD  │  ← 游戏顶栏
│ 目标 / 第几关 / 剩余时间    │  ← 子 HUD
│ ┌──────────────────────┐ │
│ │                      │ │
│ │      420×740 画布    │ │  ← 375×667 上仅约 250×441
│ │                      │ │
│ └──────────────────────┘ │
│ 操作提示 / 触屏按钮        │
└──────────────────────────┘
```

以 375×667 为例：shellbar 38px + 顶栏约 44px + 子 HUD 约 24px + 提示约 36px + 间距，
画布只剩 441px 高（约 250×441），上下被“标题类”内容占掉约 1/3 屏。

## 2. 目标与非目标

目标：

1. 玩家一键进入“只剩游戏”的状态；可随时退出，不打断、不丢进度。
2. 不支持网页全屏的浏览器（主要是 iPhone Safari）也有可用的沉浸降级，而不是按钮点了没反应。
3. 黄金矿工第一关明显更慢，形成“看准再放钩”的节奏；后期仍逐步加速。
4. 增加限量、可理解的主动道具，其中“指哪打哪”让瞄准从“等摆到角度”变成“指哪抓哪”。

非目标：

- 不做横屏重排（仍是竖屏游戏）；横屏只提示“竖屏体验更佳”。
- 不做道具商店、货币、广告或任何网络请求。
- 不修改其他 12 款游戏的玩法数值；全屏是共享能力，所有游戏自动获得。

## 3. 全屏 / 沉浸模式

### 3.1 入口与出口

| 入口 | 行为 |
| --- | --- |
| 游戏顶栏 `⛶`（44×44） | 进入全屏；再次点击或点 `⤡` 退出 |
| 开始 / 暂停弹层里的 `⛶ 全屏模式` | 同上，便于第一次发现 |
| 键盘 `F` | 切换（输入框内不拦截） |
| 浏览器 `Esc` | 退出原生全屏，页面同步回到普通布局 |
| 手机浏览器返回 / 切页 | 浏览器自行退出全屏，进度照常自动保存 |

进入后顶栏只保留：`‹`、紧凑标题、暂停、静音、退出全屏。分数 HUD、子 HUD、操作提示隐藏。
原因：13 款游戏都已经把分数/关卡/时间画在画布内部（逐款核对过 `draw.label`），
DOM HUD 在普通布局里是“补充”，在全屏里只会重复占高度；标题在顶栏、不占画布高度，保留它便于确认当前游戏。

### 3.2 原生全屏与降级

```
点击 ⛶
  ├─ 浏览器支持 Element.requestFullscreen
  │    → document.documentElement.requestFullscreen({ navigationUI: 'hide' })
  │    → 成功：原生全屏 + body.arcade-immersive
  │    → 失败：保留 body.arcade-immersive（CSS 沉浸）
  └─ 不支持（iPhone Safari）
       → body.arcade-immersive（CSS 沉浸）
       → 首次提示：可“添加到主屏幕”获得更纯粹的显示
```

CSS 沉浸不是“假全屏”：它固定页面、隐藏 shellbar/重复 HUD/提示、保留紧凑标题，按 `100dvh` 重排，
在 iPhone 上仍能多出约 100–130px 的游戏高度；只是无法隐藏 Safari 自己的地址栏。

### 3.3 全屏布局规则

- `body.arcade-immersive`：`overflow: hidden`，页面固定为 `100dvh`。
- 顶栏高度固定内容（约 52px，含 `safe-area-inset-top`），画布区吃掉剩余高度。
- 画布保持 420:740，不拉伸：
  `height = min(可用高度, 可用宽度 × 740 / 420)`。
- 四周使用 `safe-area-inset-*`，刘海屏不压字、不裁画布。
- 暂停/开始弹层仍在画布内，居中；退出全屏后弹层自然回到普通布局。
- 横屏（`orientation: landscape` 且高度 ≤ 560px）显示小提示“↻ 竖屏体验更佳”，不阻断操作。
- 普通模式顶栏也做了减法：≤460px 隐藏 DOM HUD（画布内已有分数/关卡/时间，最高分仍可在中心页/结算查看）并把返回链接收成箭头，给新增的全屏按钮让位；≤360px 再缩小标题。这样 375/320 上标题不会被裁切。

375×667 实测预期：画布由约 250×441 → 约 349×615（面积约 1.95×）。
390×844 上高度受宽度约束，画布约 390×687。

### 3.4 记忆与自动恢复

- `Prefs` 新增 `immersive`（布尔，默认 `false`），沿用 `studiokit:arcade:prefs:v1`，不新增 key。
- 用户主动进入 → 记为 `true`；主动退出 / 浏览器退出 → 记为 `false`。
- 记忆为 `true` 时，下一次在开始/继续弹层上点任意按钮，会在同一个用户手势里自动恢复全屏。
- 不在页面加载时自动请求（浏览器会拒绝无手势请求），也不强制桌面用户全屏。

### 3.5 平台与风险

| 环境 | 预期 |
| --- | --- |
| Android Chrome / Edge / Firefox | 原生全屏，可锁定竖屏时尝试 `screen.orientation.lock('portrait')` |
| iPhone Safari | CSS 沉浸；无网页全屏 |
| iPad Safari | 通常支持原生全屏；失败自动降级 |
| 桌面 Chrome / Edge / Firefox | 原生全屏；`F` 切换 |
| 桌面 Safari | 支持时原生，否则 CSS 沉浸 |
| 内嵌 WebView / iframe 预览 | 可能被权限拒绝；自动降级为 CSS 沉浸 |

风险与处理：

- **布局抖动**：`fullscreenchange` / `resize` / `ResizeObserver` 三路重算画布；切换后补发两次 resize。
- **Esc 同时暂停**：浏览器通常不把退出全屏的 Esc 交给页面；即使交给页面，暂停也是可接受行为。
- **iOS 地址栏**：CSS 沉浸无法隐藏 Safari 地址栏，用提示说明“添加到主屏幕”，不假装成功。
- **误触退出**：退出按钮仍在顶栏，与暂停/静音分开；全屏不会自动暂停，退出不丢局。

## 4. 黄金矿工

### 4.1 摆速

摆长固定 88，单摆周期 `T = 2π√(L/g)`，最低点速度 `v = √(2gL(1−cosθ))`。
只改 `LEVEL_SPECS.swing`，不改物品、目标、时长与判定。

| 关卡 | 原摆速 | 新摆速 | 周期（约） | 说明 |
| --- | ---: | ---: | ---: | --- |
| 1 | 520 | **300** | 2.58s → 3.40s | 第一关周期 +32%，最低点速度约 −24% |
| 2 | 650 | **380** | 2.31s → 3.02s | 稳定练习 |
| 3 | 780 | **470** | 2.11s → 2.72s | 引入炸药 |
| 4 | 910 | **580** | 1.95s → 2.45s | 高价值 + 高风险 |
| 5 | 1040 | **700** | 1.83s → 2.23s | 限时冲刺 |
| 无尽 | +70/关，上限 1500 | **+80/关，上限 1300** | — | 后期仍会明显加快，但不会失控 |

HUD 的“摆速 ×”改为相对第一关 `300` 显示，第一关为 `1.0×`。

### 4.2 道具（限量补给）

| 道具 | 效果 | 初始 | 每关补给 | 上限 | 消耗时机 |
| --- | --- | ---: | --- | ---: | --- |
| 🎯 指哪打哪 | 激活后点任意金块/钻石/石头，钩爪立刻转向该目标直线抓取 | 2 | +1 | 3 | 点中有效目标时 |
| ⏳ 加时 | 当前关 +10 秒 | 1 | 偶数关 +1 | 2 | 点按钮时 |
| 💪 强力绞盘 | 下一次成功抓取无视重量，回收速度 980 px/s（普通上限 840） | 1 | 每 3 关 +1 | 2 | 成功入账时 |

设计取舍：

- **不做商店**。通关即补给，不引入货币/经济系统，符合离线、碎片时间定位。
- **指哪打哪不是秒抓**：钩爪仍要从 88px 起点飞到目标，再按重量回收，保留物理感；
  只是跳过“等摆角”，因此不会变成无脑点击。
- **指哪打哪不会误抓炸药**：瞄准 TNT 只提示、不消耗；飞行途中忽略其他物品，
  避免“明明点的是钻石却被路过的炸药炸掉”的不公平。
- **加时不能无限叠**：当前关最多比基础时长多 10 秒；已满时按钮提示“留到后面再用”，不扣次数。
- **绞盘在成功入账时才扣次数**：抓空或炸掉不浪费；上弦状态跨关保留。
- 所有道具使用后立即写一次局内档；暂停、离开页面仍走原有自动保存。

### 4.3 界面

道具条贴在画布底部，不额外占用页面高度：

```
┌────────────────────────────────┐
│                                │
│            游戏画布             │
│                                │
│ ┌────────┬────────┬────────┐  │
│ │ 🎯 指哪 │ ⏳ 加时 │ 💪 绞盘 │  │ ← 半透明渐变，44px+
│ │  打哪 ② │   +10s ①│   ②    │  │
│ └────────┴────────┴────────┘  │
└────────────────────────────────┘
```

- 3 个按钮等分，图标 + 名称 + 剩余次数徽标；手机上（视口 ≤620px，舞台通常只有 250–350px）隐藏名称，只留图标与次数。
- 激活态用 `aria-pressed` + 金色描边；次数为 0 时禁用并变淡。
- 快捷键 `1 / 2 / 3`；按钮均有完整 `aria-label`（含剩余次数）。
- 物品生成下限从 `H−24` 提高，并按道具条的实际 CSS 高度换算成逻辑坐标（约 `H−130`～`H−180`，视屏宽而定），不会生成在道具条后面；旧档里的物品在恢复时也会被抬到该下限以上。钩爪伸到该下限即回收，不再钻到道具条后面。
- 达标提示按钮也从固定视口底边改为画布内、道具条上方，避免窄屏上挡住道具。
- 瞄准态在画布上画虚线、目标脉冲圈与“锁定”；点击空白/炸药有提示且不扣次数。
- 暂停、结算时自动取消瞄准态（不消耗次数）。

### 4.4 存档兼容

- 局内档仍是 `studiokit:arcade:runs:v1` / Schema v1，只在 `data` 内新增：
  `tools: { aim, time, winch }`、`winchArmed`。
- 旧档没有这些字段 → 恢复为初始补给，其余进度照旧。
- 读取时全部做 `clamp`，非法值不会产生负次数或超上限。
- 最高分、进度 key、导出格式均不变。
