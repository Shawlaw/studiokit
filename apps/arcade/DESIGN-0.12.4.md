# Arcade 0.12.4 设计：修复 LOD 误按层数触发（近景集装箱细节丢失）

基线：0.12.3（2026-11-22 已双端发布）。本版只改层塔（`apps/arcade/games/pendulum-tower.html`）与门禁/文档。

## 1. 问题

Owner 反馈：「你改出 bug 了吧？箱子落下后的细节没有了？变成了一个纯色块？」

这是 0.12.3 引入的回归。0.12.3 为支持 1000 层全览加了 LOD（层级细节），判据写成：

```js
const dense = boxes.length > 60 || view.scale < 0.35;
```

`||` 左边那一项是错的：**层数多 ≠ 看不清**。只要塔超过 60 层，即使玩家处在正常的 1:1 跟随视角（每只集装箱在屏幕上仍是 64×40px，波纹、角件、编号全都该看得见），也会被判定为 `dense`，整塔退化成纯色方块。

## 2. 修复

1. **LOD 只由缩放决定**：`const dense = view.scale < 0.2;`
   - 阈值取 0.2 而不是 0.5：0.2 以上箱体屏幕尺寸仍有约 13×8px，波纹/角件看得见，保留完整细节更好看；只有真正强压缩（120 层 ≈0.10、1000 层 ≈0.013）才退化为色块。
2. **性能改为视口裁剪**：正常视角按世界 y 范围裁掉不可见的箱子（`halfViewWorld = H/2/scale + 2×BOX_H`）。这样「近景保留完整细节」与「千层塔不卡」可以同时成立——实测 1000 层近景每帧只画 23~24 只箱子（共 1002）。
3. **结构轮廓**只在 `view.scale < 0.35`（真正的压缩视图）时绘制，不再按层数判断。
4. 新增 `#test` 探针 `physicsInfo().renderLod = { dense, scale, drawnBoxes, totalBoxes }`，供门禁守住「近景必须是完整集装箱」。

## 3. 验收（`tools/arcade_tower_test.mjs` 19 → 20 项）

| 新增项 | 断言 |
| --- | --- |
| TP-12 LOD 只跟缩放走 | 3 / 40 / 120 / 1000 层在**正常近景**：`view.scale≈1`、`renderLod.dense === false`（必须有细节）、`drawnBoxes ≤ 40`（裁剪生效）、≥120 层时 `drawnBoxes < totalBoxes`；切全览后：40 层（scale 0.291）仍 `dense=false` 保留细节，120 层（0.103）与 1000 层（0.013）为 `dense=true`；全览必须 `fitsOnScreen` |

## 4. 兼容与不变量

- 无 localStorage key / Schema / 挑战关卡数据变更。
- 0.12.3 的「全览无缩放下限」保持不变（40/200/1000 层都完整入屏）。
- 近景绘制路径对常规层数完全恢复 0.12.2 的样子（含集装箱编号、属性图标、波纹、角件）。
- 其它 15 款游戏、`engine.js`、`arcade.css` 零改动。

## 5. 教训

LOD 的判据必须是**屏幕尺寸**（本例即缩放），不能是数据规模。层数多只影响「要画多少个」，用裁剪解决；「每个画多细」只能由缩放决定。
