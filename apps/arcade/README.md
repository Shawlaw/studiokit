## 0.13.2 两条真机反馈修复：PWA「检查更新」版本来源 + iOS 游玩时长永久停摆（2026-11-22 已双端发布）

Owner 反馈：①安装到主屏幕的 PWA 点「🔄 检查更新」，提示里是**已安装版本**而不是线上最新版本；②iPhone 主屏 PWA 玩一天后中心页「累计时长」一直是 `0 分钟`，但积分记录表格有数据。两条都用无头 Chrome 复现并按根因修复（设计与复现输出见 `DESIGN-0.13.2.md`，**挑战/玩法/存档零改动**）：

- **游玩时长永久停摆（iOS 主屏 PWA）**：16 款游戏共用同一个 `Playtime`，旧实现 `startSegment()` 依赖 `focused`，而它只在 window `focus` 事件里恢复；iOS 主屏 PWA 的 `focus` 不可靠（回前台常常只有 `visibilitychange`、页面也不重新加载），漏一次 `focus` 后这一页的计时永久停摆，但 `scores:v1` 仍照常写入 —— 复现：先 `blur` 再无 `focus` 时 `snake-run ms=0`、结算 `durationMs: 0`，再点按也不恢复。现在只认「页面可见 + 弹层关闭」：删除 focus 门槛（失焦仍立即落盘，暂停由游戏自动暂停 + 暂停层承担），`visibilitychange` / `focus` / `pageshow` / 用户点按按键 / 15 秒 tick 都会自愈，`recordRound()` 结算后续开时间片。
- **更新检测版本来源错了（主因）**：`checkForUpdate()` 旧实现返回页面自身的 `ARCADE_VERSION`（= 已安装版本），从不读取线上版本。现在解析线上 `sw.js` 的 `VERSION` 作为最新版本，再与页面/SW 版本比较，返回值包含 `latestVersion` / `installedVersion` / `pageVersion` / `updateReason`。
- **SW 从不广播新版本**：旧 `firstActivation` 标志恒为 false，`arcade-sw-update-ready` 从未发出。现在 `activate` 在清理旧缓存前用「旧版本缓存是否存在」判断升级接管，确认是升级才广播当前 `VERSION`。
- **`updateFound` 时序抽奖 / 提示误导**：改为按版本号比较判定（新 SW 已接管但页面未刷新也提示刷新）；`controllerchange` 不再覆盖已知版本号；读不到线上版本时提示「检查更新失败」而不是「已是最新」。
- **中心页文案**：横幅与按钮提示都同时显示最新版本与当前版本，例如「发现新版本 v0.13.3（当前 v0.13.2），刷新后生效。」。
- **门禁**：`arcade_pwa_update_test` **9/9**（新增真实发版链路与读取失败两条）；smoke **108/108**（新增 3 项 iOS 漏发 focus 的计时回归）、tower 23/23、zen 14/14、calm 17/17、review 5/5、interaction 5/5、immersive 32/32、gameplay all 104/104 + base 22/22（11 场景 ×2 遍）、挑战矩阵 78 关、320–430px 与 standalone 布局、validate/build/inline/design 全过。
- **发布**：提交 `8493cf7` + `78858e0` ff 合入 `main`；Actions run `45002523350` 四 job 全绿（Validate and build / Deploy GitHub Pages / Deploy Cloudflare Pages / Verify both deployments）；CI 与本地 `tools/verify_deploy.py` 均 **41/41** 双端逐文件一致（arcade 0.13.2 / badge 2.2.1 / venue 0.2.0）；双端线上无头 Chrome 各 8 项全过（中心页 0.13.2 + 检查更新返回线上 0.13.2 且不误报、SW 握手 0.13.2、线上 `sw.js` 含升级广播修复、缓存键 `studiokit-arcade-0.13.2-v1`、游戏页可加载、0 console error）；真机 iOS 更新提示时机与游玩时长/积分记录时长待 Owner 复测（UNVERIFIED）。

## 统一体验

- **由简到难**：每款游戏内部都有渐进难度（关卡、速度、障碍、敌机密度等）；中心页默认按难度排序，也支持按类型筛选和关键词搜索。
- **全屏沉浸**：游戏顶栏 `⛶`（或键盘 `F`）或弹层内的「全屏模式」按钮显式进入全屏；支持 Fullscreen API 的浏览器请求原生全屏并尝试锁定竖屏，不支持时（主要是 iPhone Safari）自动退化为 CSS 沉浸布局：隐藏站点导航、重复 HUD 与提示、保留紧凑标题，画布按 420:740 吃满可用空间，四周适配 safe-area。**点开始/继续不会自动进入全屏**，避免把普通触控误当成全屏指令；退出全屏不会暂停或丢进度。
- **随时暂停**：每个游戏顶栏都有暂停按钮，键盘 `P` / `Esc` 也可暂停；页面失焦或切到后台会自动暂停。
- **禅模式（0.8.1）**：俄罗斯方块开始弹层第三个入口「🧘 禅模式」为无限局（不设 40 行收局）；不冻结时速度随等级提升，按 `Z` 或道具行「❄ 冻结提速」后速度停在当前等级、等级与行数继续累计，再按「▶ 恢复提速」立即追平；0.8.2 起冻结按钮并入道具行、不再单独占一行。结算显示「禅模式结束」并把本局积分写入中心页积分记录（不写经典最高分）。刷新可恢复冻结状态与速度。
- **触屏友好**：俄罗斯方块采用双手分区按钮：左手 `← / →` 大键横移（按住连续移动），右手 `↻` 旋转、`↓` 按住加速、`⇓` 点按落底；加速按 0.06s/格逐格下落且按住时青色高亮，不会立即锁定；落底为实心金色按钮，点按立即锁定并带短促下沉/金色脉冲与轻震。每个按钮带图标与文字；画布不再承担隐藏触摸区，点按/按住画面不会误操作。贪吃蛇触屏使用左右分区的「↺ 左转 / ↻ 右转」双按钮，相对蛇头当前方向每次转 90°，快速连点按格依次执行；键盘、WASD 与滑动仍为绝对方向。极速车道提供左右变道按钮，一次点击只移动一条车道；其余游戏使用拖动、半屏触摸或滑动。
- **公平性与节奏**：星海突击按 4 阶段波次推进并设敌机/敌弹上限，每关 30 秒后进入 Boss 战，Boss 分三档火力并带血条；雪铃同一铃铛一局只计一次分；影跃只生成可达平台并延迟引入移动/易碎机制；极速车道生成时保留可达安全走廊；层塔前 3 层显示落点投影；黄金矿工前 5 关有不同物品池/炸药/摆速，并支持达标提前结算。

## 数据与隐私

- 无任何网络请求、埋点或第三方资源；音效由 WebAudio 实时合成。Service Worker 只缓存同源 Arcade 页面与 `shared/` 资源，不访问第三方域名。
- localStorage 键（均带 `studiokit:arcade:` 命名空间）：
  - `studiokit:arcade:progress:v1` — 全部游戏的 `{ high, plays, lastAt, lastScore }`（Schema v1；`lastScore` 为兼容扩展字段）。
  - `studiokit:arcade:runs:v1` — 未完成的局内进度快照（Schema v1，每款游戏一条，含 `savedAt` / `score` / `summary` / `data`）。0.7.0 的道具次数、计时器和武装状态只追加在各游戏 `data` 内；旧档缺字段时按每局初始补给恢复，不迁移 key、不改变 Schema。
  - `studiokit:arcade:prefs:v1` — 偏好（`muted` 静音、`immersive` 上次全屏选择；0.6.0 起仅记录，不再因点开始/继续自动进入全屏，旧对象缺少时按关闭处理）。
  - `studiokit:arcade:playtime:v1` — 游玩统计（0.5.0 新增，Schema v1）：按游戏保存 `ms` 总时长、`count` 完成轮次、`lastAt`、最近 30 轮 `rounds`（`at` / `ms` / `score` / `newHigh`）与最近 120 天 `days` 日汇总。旧版本没有该 key 时按空统计处理。
  - `studiokit:arcade:scores:v1` — 积分记录（0.8.1 新增，Schema v1）：`records` 数组按时间最新在前保存每局 `{ at, gameId, mode, score, lines, level, durationMs, detail }`，最多 300 条；`mode` 为 `classic` 或 `zen`。旧版本没有该 key 时按空记录处理；损坏数据读取时 fail-closed，不删除原值。
  - `studiokit:arcade:meta:v1` — 引擎通用游戏数据（0.13.0 新增，Schema v1）：`{ schemaVersion: 1, games: { <gameId>: {...} } }`，按游戏 ID 存各游戏自己的长期数据（普通 JSON、单游戏 ≤32KB、损坏 fail closed 且不覆盖原值）。目前只有星海突击使用：`games['star-raid'].hangar = { v: 1, formula: 1, credits, upgrades: { hull, power, engine, energy, bay, wing }, runs, best }`。旧版本没有该 key 时按空处理；清空只需删键或调 `A.GameMeta.clear(gameId)`（中心页「清除记录」同步清除）。
- 中心页支持导出/导入 JSON 备份（`format: studiokit-arcade-progress`，含 `schemaVersion` / `appVersion` / `exportedAt` / `state` / `runs` / `playtime` / `challenge` / `scores`；0.13.0 起另有可选 `gameMeta`）。旧备份没有 `runs` / `playtime` / `challenge` / `scores` / `gameMeta` 字段时仍可导入，并保留当前对应的局内进度、统计、挑战记录、积分记录或附加存档（机库）；导入失败会回滚相关存储 key。
- `gameMeta`（0.13.0）：`A.GameMeta` 的导出快照——`exportData()` 返回 `{ schemaVersion: 1, games }`，`importData()` 校验 Schema 与游戏 ID 白名单后写入，返回 `{ ok, count, skipped }`；备份 JSON 用同名字段 `gameMeta`。旧备份没有该字段时保留当前值，导入失败整体回滚（含 meta key）；既有备份字段含义不变。
- `engine.js` 顶部的 `ARCADE_VERSION` 需与注册表 version 保持同步（`validate_site.py` 会检查）。

### 引擎通用 meta key 与旧档兼容（0.13.0 回滚说明）

- **key 变化**：0.13.0 **没有**为机库新增专属 key，而是复用引擎新增的通用游戏数据 `studiokit:arcade:meta:v1`（Schema v1，API `A.GameMeta.get/set/clear`）；`progress:v1` / `runs:v1` / `prefs:v1` / `playtime:v1` / `scores:v1` / `challenge:v1` 的 key 与 Schema 版本都不变。
- **局内存档（`runs:v1`）**：星海突击 `serialize()` 在 `data` 内新增 `run` 字段（`power` / `energy` / `maxEnergy` / `depleted` / `items` / `formationCharges` / `formationTimer` / `combo` / `comboTimer` / `creditsBonus` / `refitOfferIds` / `refitChosen` / `seed` / `lance` / `freezeTimer`），挑战分支为 `run: null`，结构不变；旧档缺这些字段时按默认值恢复，不迁移、不中断旧局。
- **机库字段**：`games['star-raid'].hangar`，`formula: 1` 锁定星币公式版本；非法 JSON / 单游戏超过 32KB / 越界数值按 fail closed 回退默认，且不覆盖原值。
- **备份**：新增可选 `gameMeta` 字段；旧备份没有该字段时**保留当前机库**（不当作空机库覆盖），导入失败整体回滚相关 key（含 meta key）。中心页「清除记录」与 `Progress.resetGame/resetAll` 会调用 `A.GameMeta.clear(...)` 同步清理。
- **回滚**：删除 `studiokit:arcade:meta:v1` + 还原 `engine.js` / `star-raid.html` 即可；旧版页面会忽略 `run` 字段与 `gameMeta`，用户的 `progress:v1` / `runs:v1` / `scores:v1` / `challenge:v1` 不受影响。回滚步骤与设计见 `DESIGN-0.13.0.md` §7。

## 已知边界

- 黄金矿工的道具状态写在既有局内档 `data.tools` / `data.winchArmed` 中，仍是 Schema v1；旧档没有字段时按初始补给处理。
- 星海突击 0.13.0 的星币与机库只在本机：没有排行榜、云存档或跨设备同步，清除站点数据会丢失（请导出备份）。只有经典模式结算星币（`floor(score / 16)` + 军费补给）与读改装，**挑战 6 关不读机库、不写星币**；机库改装上限固定（`hull` 3 / `power` 5 / `engine` 5 / `energy` 5 / `bay` 1 / `wing` 3），不设可无限叠加的成长。320/375/390/430px 的机库面板、道具按钮与整备卡需按 `DESIGN-0.13.0.md` §8 验收，真机触控与手感仍为 UNVERIFIED（门禁尚未执行，结果以实际输出为准）。
