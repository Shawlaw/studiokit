# Arcade 0.19.0 设计：矮视口紧凑布局与单手触屏

基线：0.18.1（2026-11-24 已双端发布）。本版已于 2026-11-25 合入 `main` 并双端发布（Actions 四项任务成功，双端 87/87 文件一致）。真机手感仍 UNVERIFIED。

范围：只改输入、布局与弹层。玩法数值、计分、关卡数据、存档 Schema 与 localStorage key 全部不变；78 关挑战数据零改动；不改共享的 `shared/site.css` / `shared/site-shell.js`。

## 1. 背景与问题（实测，基线 `a6b6dd3`）

Owner 要求按「路上走着玩 / 地铁站着玩 / 等车坐着玩」三种场景审视 16 款游戏的交互。先做了一轮只读评审：16 款游戏逐行读完，并用无头 Chrome 在 16 款 × 8 档视口下实测开局、游玩、失焦与沉浸四种状态。结论：

1. **矮视口的浏览器标签页是系统性盲区。** 门禁的四档视口（`320×568 / 375×667 / 390×844 / 430×932`）全是整机高度，没有一档扣掉地址栏和工具栏。在 375×548 下：
   - 16 款里有 10 款的「开始游戏」首屏不可见——弹层面板被限制在舞台高度内滚动，手机上没有滚动条提示；星海突击在沉浸模式下仍然一个按钮都看不到。
   - 画布普遍只占屏幕 25–32%，两侧各空出近 100px；顶部 100px 被站点壳条和游戏顶栏占用，底部约 130px 被道具行和两行键盘提示占用。
   - 俄罗斯方块页面溢出 56px，六个操作键下半部分落在首屏之外。
2. **4 处确定的缺陷。**
   - 记忆翻牌、贪吃蛇、雪铃、层塔的挑战选关层「返回开始」只有定义没有绑定，点击无反应；此时暂停键禁用，玩家只能被迫开一局挑战或离开游戏页。
   - 黄金矿工具品坞容器不接收指针事件，按钮间隙和内边距处的命中元素是画布——点偏一点就放钩。
   - 上述俄罗斯方块矮视口溢出。
   - 上述矮视口下开局按钮不可见。
3. **拇指区暂停只有俄罗斯方块有。** Owner 在 0.8.4 的反馈原话是「暂停按钮不方便，主要在地铁上玩」，当时只给俄罗斯方块加了拇指区暂停键。其余 10 款实时游戏的暂停键仍在顶栏（屏幕 8–13% 高度），单手够不到。
4. **所有游戏点「继续」后零宽限**，画面立即恢复运行；拇指还在从屏幕中部回到操作区的路上，方块已经在下落、弹幕已经在飞。
5. **结算弹层没有防误触**：连点类游戏在死亡瞬间拇指往往还在点，「再来一局」→「开始游戏」两下就能非本意地重开。
6. `career_96_missions` 门禁在基线上本来就是红的：贪吃蛇夹具还在找 0.14.0 的相对转向按钮 `[data-turn]`，而 0.18.1 已换成固定四向键。

## 2. 设计

### 2.1 矮视口紧凑模式（`≤620×700`，`arcade.css` 末尾）

- **收起站点壳条**：它和游戏顶栏重复显示标题，矮屏只留游戏顶栏；返回改用顶栏自带的箭头（≥44px）。独立窗口下顶部安全区原本由壳条承担，改由游戏页自己让位，多出的内边距从舞台高度里扣回。
- **底部说明行让位给画布**：它以键盘键位为主。职业委托把这一行换成戏内目标，所以职业对局里保留。
- **把高度还给画布**：各条舞台高度公式原本按「说明行可见」标定。引擎在页面加载和尺寸变化时量出说明行的自然高度写进 `--ac-hint-refund`，紧凑模式的 CSS 把它作为返还量加回画布。向下取整，宁可少 1px 也不让页面多出可滚动的 1px。
- **弹层改为贴底部的底部弹层**：说明文字在弹层内部滚动，按钮始终可见并落在拇指区。弹层从隐藏变为显示时给舞台加 `has-overlay`，让它盖到顶栏之上。
- **选关 / 机库面板同样提出来**：紧凑模式下舞台只有 200 多像素宽，面板挤在里面又窄又要滚。13 款选关面板和星海机库面板改为从顶栏下方（62px）起铺满屏幕。
- **拇指抬升刻意不动**：`--ac-thumb-lift` / `--block-pad-lift`（0.12.0）解决的是按钮离「设备」底边太近，与视口高度无关，独立窗口和全屏在矮屏上同样需要。实现过程中曾把矮屏的抬升量从 36px 降到 12px，`arcade_immersive_buttons_test` 拦下了这个回退（按钮距屏底 18px < 38px），已改回。
- 高屏（390×844 / 360×780 / 430×932）不走紧凑模式，布局与 0.18.1 逐像素一致。

### 2.2 拇指区暂停（引擎 `bindPause`）

页面在底部操作区放置 `[data-thumb-pause]`，引擎统一绑定点击并同步禁用态：

| 放法 | 游戏 |
| --- | --- |
| 道具行行尾独立一格（56px，其余列照旧等分） | 雪铃、重力翻转、影跃、层塔、极速车道、贪吃蛇、砖块计划、打地鼠 |
| 画布右下角悬浮钮 | 星海突击（道具行列数已满；相对拖动下这块角落不挡操作） |
| 道具坞第 5 格；画布窄于 255px 时改悬浮在画布下方 | 黄金矿工 |
| 两组操作键之间（0.8.4 起已有） | 俄罗斯方块 |

- 暂停键样式刻意低调、宽度固定：它紧挨限量道具，但暂停点错了只是暂停，道具点错会消耗次数。
- 重力翻转、砖块计划原先在挑战模式隐藏整行道具，现在只收起道具按钮，暂停键留在原位。
- 没有把俄罗斯方块的「双击画布暂停」推广到其它游戏：它们的画布本身就是主操作面，双击是合法连点。

### 2.3 恢复门（引擎 `createLoop`）

触屏会话里点「继续」后只解冻画面、不推进模拟，提示「点按屏幕继续」，下一次真实触控才恢复：

- 拖动 / 按住类（星海突击、影跃、雪铃、砖块计划、方块横移）读的是 `pointer.down`，开门的那一下自然生效。
- 点按类（重力翻转、层塔、矿工、地鼠、极速车道的半屏点按）读的是按下沿，被吞掉——不翻转、不放箱、不放钩。
- 操作键（方块、贪吃蛇方向键、极速车道变道键、各类道具）在 `pointerdown` 时直接生效，按第一个键即恢复并执行。
- 只认 `isTrusted` 事件：鼠标会话保持「点继续立即恢复」，自动化与自测注入的合成事件行为不变。
- 恢复门期间不计入有效游玩时长；期间切后台照常自动暂停。

11 款实时游戏接入。5 款棋牌益智没有计时压力，不接入。

### 2.4 结算防误触（引擎 `createOverlayUiBase`）

结算弹层从隐藏变为显示后的 450ms 内面板不接收指针，按钮淡入。只拦真实触摸 / 点击；键盘激活与程序化 `click` 不受影响。星海突击的 CLEAR 整备面板同样受保护。

### 2.5 逐游戏交互改进

| 游戏 | 改动 |
| --- | --- |
| 星海突击 | 道具按下即触发；经典模式空槽收起为一格「军械 n/N」，三个主动道具变宽（割草模式槽位常满，不变）；窄屏开局文案只留要点 |
| 影跃 | **上滑影冲**：转向的拇指不抬指，快速上滑即按当前按住的方向影冲。单手也能做到「按住方向 + 定向影冲」 |
| 雪铃、影跃 | **半屏方向锁**：落指按所在半屏定向并锁定，换边需越过中线 40 逻辑像素。抖动或急刹时手机相对拇指的位移不再让角色瞬间反向 |
| 砖块计划 | **相对拖动**：挡板跟的是指尖位移（增益 1.2）而不是瞬移到指尖位置，手指可以放在画布任意处，不再挡住挡板和来球；发球判定 8px → 14px |
| 二十一点 | **按下预览、抬起确认**：按下只高亮候选，抬起时指尖在哪个按钮上就执行哪个，滑出即取消 |
| 记忆翻牌 | 命中取「离指尖最近的牌心」，牌间间隙不再是指针死区；同样改为抬起确认 |
| 2048 合成 | 撤销键放进道具行行尾（与顶栏按钮共用 `undo()`，快捷键 Z 不变） |
| 打地鼠 | 经典模式也认第二根手指，坐着双手时可以双拇指一起敲 |
| 贪吃蛇 | 高屏上棋盘与方向键作为一组贴到页面底部，空白留在顶部，方向键落进拇指区 |
| 动作类游戏 | 道具键触屏按下即触发（`A.bindPress`），鼠标与键盘仍走 click，抬指不重复触发 |

### 2.6 测试同步（有意变更的断言）

- `career_fixture_snake-run.mjs`：把「相对转向后的目标方向」换算成固定四向键再按。这是基线上就红的门禁，不是本版引入的行为变化。
- `arcade_smoke.mjs`：返回入口取当前可见的那个（壳条链接或顶栏箭头）；「全屏画布比普通模式高 60px 以上」改为 40px 以上——紧凑模式已把壳条与说明行的高度让给普通模式（375×667：441 → 523），全屏的增量从 137px 降到 55px，各紧凑视口下最小增量约 48px。
- `tools/challenge/gravity-flip.mjs`、`brick-breaker.mjs`：挑战模式断言由「整行隐藏」改为「道具按钮收起且禁用、拇指区暂停键保留并可用」。

### 2.7 与 0.18.2 的合并：PWA 升级迁移策略必须跟着改

开发期间 `main` 先发布了 0.18.2（修复 Cloudflare Pages 预载后断网跨页失败）。把两边真正合并时，除了版本号冲突，还有一处**语义冲突**：

- 0.18.2 的 `carryPreloadedGames()` 把 `0.18.1-v3` 缓存里的游戏 HTML **逐字节复制**进新缓存。这在 0.18.2 成立，因为那一版没有改游戏页。
- 0.19.0 改动了全部 16 款游戏页和引擎。沿用这套复制会得到「新引擎 + 旧页面」：旧页面没有 `data-thumb-pause`、没有挑战选关返回绑定、没有新的道具坞结构；而且对已经从 0.18.2 升级的用户，`0.18.1-v3` 缓存根本不存在，迁移直接失效。
- 合并树上 `career_pwa_offline` 的 P16 当场复现了这个问题（17/18，P16 失败）。

**改法**：旧缓存只用来取「预载过哪些游戏」的 URL 清单（遍历所有 `studiokit-arcade-` 前缀的旧缓存，不限定某一个版本名），安装时逐个 `fetch(..., { cache: 'reload' })` 重新取当前版本页面写入新缓存；安装时没网就留空，绝不复制旧字节。测试同步改成在旧缓存里种入一页带 `STALE-0.18.2-PAGE` 标记的假页面，升级后断言缓存里是含 `data-thumb-pause` 的 0.19.0 页面且不含旧标记。

## 4. 兼容与不变量

- 不改任何 localStorage key / Schema（progress / runs / prefs / playtime / challenge / scores / meta 全部不变），不改生涯 IndexedDB。
- 不改玩法、计分、关卡数据、AI、难度曲线与挑战判定。
- 鼠标与键盘行为不变：鼠标会话不进恢复门，道具仍按 click 生效，键盘快捷键照旧。
- 独立窗口与全屏的拇指抬升量不变。
- 路径全部相对，兼容 GitHub Pages 子路径与 Cloudflare Pages 根路径；不引入任何远程资源。
- `:has()` 只用于紧凑模式下面板的层级与弹层隐藏；不支持 `:has()` 的旧浏览器只是观感差异（顶栏可能发虚），功能不受影响。

### 5.1 合并 0.18.2 之后的复验（发布前）

`main` 在本版开发期间发布了 0.18.2，两边真正合并后又把整棵树导出到仓库外，串行跑了一轮完整聚合门禁 + 4 个独立门禁：

- **通过**：静态与纯 Node 全套、career_db 38/38、backup 34/34、a11y 75/75、reachability 165/165、run_resume 45/45、**career_96_missions 16/16 游戏、96/96 档、3792/3792 检查**、career_mobile 318/318、campaign_e2e 700/700、冒烟 117/117、zen 17/17、calm 5/5、review 5/5、gameplay_all 104/104、gameplay_base 22/22；独立门禁 interaction 5/5、immersive_buttons 42/42、pwa_update 9/9、tower 23/23。
- **career_pwa_offline 17/18**：P16 暴露 §2.7 的迁移缺陷（真缺陷，不是偶发）。修复 SW 与 P16 后在最终树上重跑 **18/18**；冒烟 117/117、pwa_update 9/9 也在修复后的最终树上重跑通过。
- **career_world_state**：`Chrome DevToolsActivePort 未就绪`（启动超时），单独重跑 **109/109**。
- **career_closeout**：两张表 `openedAt` 差 1 毫秒的时序竞争，单独重跑 **6/6**。
- **compact_touch**：CT-18 记忆翻牌「牌间间隙」断言失败。排查后确认是**测试本身不确定**，不是产品缺陷：
  - 落点取的是间隙正中心，该点到两张牌心等距（各 63 逻辑像素），命中哪张由亚像素舍入决定；
  - 原断言要求 `flippedIds.length === 2`，但翻出**配对成功**的一对时游戏会把 `flippedIds` 清空（实测得到 0）。
  - 修正：落点偏向第二张牌（间隙 70% 处），断言改为「第二张牌被翻出或已配对」。修正后在最终树上连跑两轮 **18/18** 通过。产品代码未改。

这一轮仍不是「聚合脚本一次性全绿」：4 项失败各自单独重跑通过，其中 P16 是需要修代码的真缺陷，CT-18 是需要修断言的测试缺陷，另两项是环境 / 时序偶发。

## 6. 已知边界 / UNVERIFIED

- **真机触控手感 UNVERIFIED**：所有布局数据来自无头 Chrome 的模拟视口；375×548、390×664 是按 Safari 带工具栏的常见可见高度取的近似值，需真机核对。半屏方向锁的 40 逻辑像素、挡板增益 1.2、上滑影冲的 56px / 350ms、结算防抖的 450ms 都是首版取值，需要 Owner 试玩后裁决。
- iOS 安全区按 0 计（未模拟刘海）；带 Home 条的 iPhone 底部按钮行会再上移 34px。
- 未模拟 Android 原生全屏（无头环境走 CSS 沉浸回退）。
- iOS 上屏幕边缘的系统返回手势是否会打断拖到边缘的操作，未验证。
- 黄金矿工在窄画布（<255px，如 375×548 标签页）下暂停键悬浮在画布下方；独立窗口且画布窄于 255px 时不显示拇指区暂停键，只能用顶栏。

- 门禁在多浏览器并发的负载下会出现偶发失败（基线副本上 `CH-MG-007` 出现过一次，单独重跑通过）。聚合门禁必须串行运行。
